# 软件工程元框架（software-engineering）目录导览

本目录是为把软件工程知识编译为 AI Agent 可直接执行的技能而设立的**工作区**：一份成文法（规范源）＋一份编译规范（编译规程）＋一组配套汇编/审计/模板文件＋变更与待办登记，全部纳入 git 管理。Agent 在推理能力较弱的 LLM 支持下，不依赖 LLM 自身的软件工程常识或临场外部知识，仅使用编译产物即可自主执行完整软件工程过程，是整个工程的目标。

新到本目录，建议阅读顺序：本 README → AGENTS.MD（目录规约）→ 《软件工程元框架成文法.md》文档定位声明 → 按任务需要进入具体文件。

## 1. 权威关系（最重要的一条）

```
《软件工程元框架成文法.md》（母本，SSOT：什么是合法的、违规如何处置）
        │  单向约束（成文法 → 编译规范），接口 = 成文法 0.23
        ▼
《编译规范.md》（如何把规范源 + 参考资料编译成 Agent 可执行产物）
        │
        ▼
编译产物（技能卡片 / 谓词模式 / 五注册表 / FM 目录 / 依赖图 / 培训与检查材料）
        │
        ▼
真实项目运行 ── 接地验收（成文法 10.2.5 六判据）；产物缺陷回馈编译规范，成文法缺口走 R2 重审门槛（7.2.4）
```

- **成文法 > 编译规范**。编译规范不得修改成文法；发现成文法缺口（规则无法编译、性质无法实现、资料无法提取）只能走 0.23.4 的 R2 通道上交，禁止自行补写或静默忽略。
- 母本是全部条款的 **SSOT**；汇编本/模板/单行本均为**派生归约本**，与母本冲突时以母本为准，冲突本身登记为汇编缺陷（0.13）。
- 参考资料（兄弟目录 `resources`）是编译输入，不是规范源；其使用受成文法 0.12 书目治理与编译规范第四章约束。

## 4. 文件间依赖关系（谁引用谁）

- 母本 → 定位指针（非内容依赖）：`编译规范.md`、`todo.md`、两份 changlog、`AGENTS.MD`（见母本文档头"配套文件说明"表）。母本的术语自包含承诺不延伸至这些文件的存在性。
- 编译规范 → 母本：全部条款引用（13.2 用例对引用精度做机械核验：编号存在性／语义范围一致性／数量型引用）；编译规范 bib_id 引用母本书目编号 1–80。
- 汇编本/裁剪模板 → 母本：每个表格行与参数都带母本条款指针（裁剪模板 §6 有全量指针索引）。
- 三份审计报告 → 母本＋`archieve/`＋两份 changlog（只读核对，不反向约束）。
- 母本附录四 → x.6 走查正文与 0.20.2 FM 表（机械映射，不推断补位）；todo 3.9 已闭合。
- git 与 changlog 的分工：**changlog 记语义裁决（为什么改、裁决是什么），git 记文件演进（改了哪些字节）**；两者并行，互不替代。

## 5. 接地编译流程（端到端）

"接地"＝框架在某具体部署中真正可执行且可验证。判定权威是母本 10.2.5 六判据；流程分四个阶段。

### 阶段 A：编译准备

1. 读本 README 与 AGENTS.MD，确认 `../resources` 在位；按母本 x.7 核对本次编译涉及条目的本地资源状态，缺失即暂停报告（编译规范 4.1）。
2. 部署规模实例化：用《部署规模裁剪模板》对档（按 1.3/2.3/5.3/8.3/9.3 三空间承载事实，不按人数），裁剪 ADR 登记（8.2.7；红线 R1–R6 不可裁）。
3. 五注册表建立接地最小集：批准角色注册表（0.5）、方法注册表、守护规则注册表、FVR、投影规则注册表（10.2.5 判据 2 要求非空）。

### 阶段 B：种子引导（单 Agent/人工种子阶段，当前所处阶段）

4. 按成文法 0.17.6 **人工种子通道**整理方法注册表初始条目（todo 3.8）：骨架源 → 成文法交叉表源 → 参考资料源 → 人工判断兜底，四层来源逐条标注；未标 `compile_usage` 的文献不得填充字段（M6）。
5. E3 bootstrap 豁免按 Waiver 五要素登记，LRM＝编译器首次成功运行；条目先入 `seed`，编译器就绪后逐条重验证，差异强制三分类（编译器缺陷／人工整理错误／成文法歧义，0.17.6(3)），禁止差异忽略（M8）。

### 阶段 C：编译执行

6. 按《编译规范》第五章编译算法执行：编译源锚定（第三章，未锚定段落按章处置）→ 参考资料映射（第四章）→ 产物生成（schema 见第二章；层次一＝技能卡片，层次二＝设计过程谓词化，10.2.3bis）。
7. 忠实性检查（第六章三判据）与 FVR 接线（母本 10.2.4）；失败按第九章 FM 目录归类，无法归类走 FM-0。
8. **多 Agent 前置门（#9）**：出现第一个多写入方部署决策时，先补齐 11.4 并发协议（乐观并发/版本向量等算法＋运行时监测＋0.21.5 五不变式验证证据）方可进入多 Agent 生产部署；单写入方场景该门平凡满足。

### 阶段 D：接地验收与运行

9. 按 10.2.5 六判据验收；无 CI 等能力缺口走既有路由（8.3 人工执行 CH-B；无 seam/probe 等见各 x.6 成例与裁剪模板违例清单），不得以能力缺口豁免硬性质。
10. 真实项目试点（todo 3.5）：产物装配→运行→收集忠实性缺陷与卡片可用性问题；编译规范修订权属人类（E7）；试点失败也是三空间事实，进演化路线图。
11. 通道终止：第一次成功编译通过对齐验证＝人工种子通道 LRM（0.17.6(4)）；此后注册表以编译产物为权威，人工种子仅历史身份。

## 7. 版本与变更纪律

- git：仓库根本目录；分支 `main`；`resources/` 已在 `.gitignore`。提交粒度建议＝一个语义批次一个提交；提交信息不替代 changlog 条目。
- changlog：任何母本/编译规范变更先追加对应 changlog 条目（裁决、波及文本、计数变化），再落盘正文；编号只追加不复用（0.22 承诺一）；历史前提失效按 0.23.6 正例 23-1 登记更正，不静默改写。
- todo：只维护当前任务与状态，完成项保留一行结论＋changelog 指针。
- 派生本（汇编本/模板/单行本）：母本修订后按 changlog 批次同步复核指针与默认值。
