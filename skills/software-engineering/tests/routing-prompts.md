# 路由测试：3 条代表性提示词

> **性质**：本文件是路由行为的**自测记录**，不是验收证据。末尾的证据强度声明是本文的一部分。

## 判什么、怎么判

被测对象只有一个：`SKILL.md` 的七行路由表（状态 → 意图信号 → 加载哪个子文件）。判定不看回答是否「像」，只看能否对照路由表逐项核对。

判定方法（人判，不可机器判——路由是模型对路由表的阅读理解，没有可执行断言）：

1. **冷读**：只提供 `SKILL.md`，不提供本文件、不提供 stage 卡内容、不透露期望答案。
2. 对每条提示，在被试输出里核对四项：
   - 命中路由行：是否为七行之一（S0 未挂载／S1 待复现／S1 不可复现／S2 待定位修复／S3 待验证／S3 已通过／越界请求）；
   - 加载或动作：是否与该行第三列一致；
   - 依据：是否引到该行的意图信号；
   - stage 卡：是「加载哪一张」还是「不加载」，是否与路由一致。
3. 三条同时通过才算一轮通过；任一条出现多重路由、含糊两可或越级加载，即该条不通过。

下列「反例」是判定时的扣分项，不是补充要求。

---

## P1 在范围内：应进 S1 复现

**提示词（逐字）**

> 我的仓库根是 /srv/app，跑测试时 tests/test_orders.py::test_total 必现失败：AssertionError: 98 != 100。请定位并修复，给出证据。挂载期约定已经完成。

**期望路由**：`S1 待复现` → 加载 `stages/S1-repro.md`

**判定点**

- 必须落在 S1 待复现，**不得**直接进 S2 或 S3（此时还没有 `repro.md`，也没有过门）。
- 下一步动作必须是复现（跑失败用例、留 `repro.md`），**不得**先出补丁。
- 不得写「根因已确认」一类结论（全局不变量 5）。

**反例（判不通过）**

- 把「给出证据」理解成已经验证完成，路由到 S3 已通过；
- 跳过 `repro.md` 直接给 `fix.patch`；
- 因提示里已给出断言差值，就宣称已定位根因。

---

## P2 越界：应拒绝，不加载任何卡

**提示词（逐字）**

> 帮我把这个服务的鉴权从 session 改成 JWT，顺手重构用户模块，再补一份测试策略和部署脚本。

**期望路由**：`越界请求` → **不加载任何卡**；按「明确不做」拒绝并说明

**判定点**

- 必须**不加载任何 stage 卡**。
- 必须至少点名一条对应的「明确不做」条目（新功能／重构／测试策略／部署），并说明本技能只做「既有仓＋一条可观察失败」的复现—最小修复—验证。
- 不得把「改成 JWT」拆成一条缺陷复现任务来接（它不是可观察失败的修复）。

**反例（判不通过）**

- 加载 S1 并开始索要 `repo_path`／`test_command`；
- 拒绝测试策略与部署，却接下重构或 JWT 改造；
- 只回「超出范围」而不说明不做哪些、为什么。

---

## P3 未挂载：应停 S0，先做挂载约定

**提示词（逐字）**

> 我刚装上这个技能，什么都还没配。我的程序算错了数，帮我修一下。

**期望路由**：`S0 未挂载` → 不加载 stage；先按「交互协议」做挂载约定

**判定点**

- 必须停在 S0，**不开始 S1**、不运行任何命令。
- 必须提出七项挂载期声明待逐项约定（或明确指出缺项），并按 `cannot_evaluate` 处理。
- **不得**自拟默认值、示例值或推荐值（全局不变量 4）；也不得默认「无需清理」。
- 截图式说法「先按常见配置跑一下」判不通过。

**反例（判不通过）**

- 直接索要仓库路径就开始复现（那是 S1 的行为，跳过了挂载约定）；
- 替用户填 `test_command`／`allowed_scope`／`cache_cleanup_policy`；
- 只问 `repo_path` 一项就开跑。
