# 卡点回流：日志怎么汇总、谁分诊、版本怎么递增

> 卡点＝技能在真实使用中卡住的地方。日志的格式与脱敏规则见 [schemas/blocker-log.md](schemas/blocker-log.md)，安装见 [PACKAGING.md](PACKAGING.md)。
> 本流程只处理卡点，不处理需求，也不做路线图；它不改变技能能执行哪些任务。

## 两条限制（先写在前面）

1. **没被触发的卡点，技能自己记不下来。** 技能没意识到、或答完了但答错了，都不会留下记录。漏触发只能靠**部署侧会话记录**和**人工抽样审计**统计。**不得把「0 条漏触发」当作成绩**——0 条可能只说明没记录。
2. **卡点日志不改变技能能执行哪些任务，也不属于任务交付物。** 它不是第五种交付物，不新增阶段、不放宽「明确不做」、不参与交付物的自动检查。要改能力边界，只能按 `SKILL.md` 的「能力边界规则」办，本流程无权代劳。

## 角色

| 角色 | 是谁 |
|---|---|
| 记录人 | 部署侧实际使用技能的人（或其值班） |
| 人审人 | 部署侧的另一人（**不得是本次被记录会话的当事人**） |
| 汇总人／分诊人 | 技能维护者（交付方） |
| 裁定人 | 人类（批准人字段新写一律 `onlookor`） |

## 六步流程

每步写：谁做 → 产出什么 → 什么条件下不得进入下一步。

### B0 采集（记录人）

- **谁**：记录人，在部署侧本地。
- **产出**：一条或数条卡点记录，严格按格式写；默认**不上传**。
- **不得进入 B1**：记录里出现真实路径、仓库名、主机名、账号、内部地址或代码片段时，先改写成抽象描述；写不抽象就丢弃该条。

### B1 人审与脱敏（人审人）

- **谁**：部署侧的另一人。
- **产出**：机器检查通过（`check_blocker_log.py` 退出码 0）＋人读完确认无残留标识；决定「提交」或「不提交」。
- **不得进入 B2**：机器检查非 0；人审发现不带点的仓库名／主机名／账号；或记录无法对应到一次真实卡点。**未过人审的记录不得进入任何汇总。**

### B2 汇总（汇总人）

- **谁**：技能维护者。
- **产出**：只含已过人审记录的汇总表，按「文件＋章节＋类型」计数，附原始记录；表头必须标注「仅统计已提交记录，不代表漏触发为 0」。
- **不得进入 B3**：汇总里含未过人审的记录；记录缺技能版本号或版本号对应不上已发布的包；同一批记录被重复计入。

### B3 分诊（分诊人；越界时转裁定人）

- **谁**：技能维护者；涉及阶段、判定规则、交付物类型或「明确不做」的变化时，必须转人类裁定。
- **产出**：每条记录的处置结论，三选一——`改说明`（写明改哪个文件哪一节）、`不改`（写明理由）、`需人类裁定`（写明争点）。
- **不得进入 B4**：结论为 `需人类裁定` 尚未裁定；或处置方式实质上新增了阶段／交付物类型／放宽「明确不做」。那属于能力边界变化，按 `SKILL.md`「能力边界规则」四条办，B3 不得直接改。

### B4 改说明与版本递增（维护者）

- **谁**：技能维护者。
- **产出**：改后的说明文件＋`SKILL.md` 的 `version` 递增＋按新版重新打包。
- **版本规则**（`version` 以 `SKILL.md` 开头为准，打包脚本读取它）：
  - **patch（X.Y.Z→X.Y.Z+1）**：只澄清表述、补例子、修错字，**不改任何判定**；
  - **minor（X.Y→X.Y+1.0）**：改通过条件、改字段、改自动检查或新增检查项，但不新增交付物类型、不放宽「明确不做」；
  - **major（X→X+1.0.0）**：改变能力边界（新增交付物类型、放宽「明确不做」），**必须先有人类批准**，再按「能力边界规则」四条执行。
- **不得进入 B5**：判定变了但对应自动检查没改；或版本号没递增；或随包示例未重跑通过（八项自动检查非全通过）。

### B5 发布与回写（维护者，部署侧自愿升级）

- **谁**：维护者打包发布；部署侧决定是否升级。
- **产出**：`dist/software-engineering-<版本>.tar.gz`＋`.sha256`＋发布说明（写清本版改了什么、**明确不包含什么**）；本轮的卡点汇总与处置结论随版本归档。
- **不得进入 B6**：打包脚本的正向或反向核对失败；发布说明遗漏「不包含什么」；版本号与包名不一致。

### B6 周期性复核（裁定人）

- **谁**：人类。
- **产出**：抽样审计结论——从部署侧会话记录里抽样，估计漏触发与错答率；结论写进下一轮汇总的附注。
- **不得进入下一轮 B2**：把「本周期 0 条卡点」当作「本周期无卡点」；抽样未做就宣称漏触发为 0。

## 一图概括

```
部署侧：B0 采集 → B1 人审脱敏 ──(未过人审即止)──▶ 提交
                                                    │
交付侧：                          B2 汇总 → B3 分诊 → B4 改说明＋升版本 → B5 打包发布
                                                    │                        │
                                                    └──── 越界则转裁定人 ◀───┘
人类：                                     B6 周期抽样复核（估漏触发）
```

## 明确不做（本流程）

- 不把卡点日志变成任务交付物，不新增阶段，不参与交付物的自动检查；
- 不用「记录条数」或「0 条漏触发」评价技能质量；
- 不自动上传、不自动提交、不自动改说明；
- 不接管需求、路线图、发布计划。
