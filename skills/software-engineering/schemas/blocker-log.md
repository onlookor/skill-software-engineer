# schema：卡点日志（blocker-log）

> 性质：部署侧的诊断记录，**不是任务交付物**，不参与 V01–V09 判定，也不改变技能能执行哪些任务。
> 默认不上传；由人看过再决定是否提交到回流汇总处。

## 两条必须写明的限制

1. **未触发的情况，技能自身记不了。** 只有「技能自己意识到卡住了」才可能留下一条；技能没意识到、或直接答完但答错了，不会产生记录。因此漏触发只能靠**部署侧会话记录**与**人工抽样审计**去统计。**不得把「0 条漏触发」当作成绩**——0 条可能只说明没记录，不说明没发生。
2. **卡点日志不改变技能能执行哪些任务。** 它不是第五种交付物，不新增 stage、不放宽「明确不做」、不参与交付物校验；它只是描述卡在哪。扩张锁定的四条仍按 `SKILL.md` 执行。

## 只允许四类内容

一条记录恰好五个键，对应四类内容；**多一个键、少一个键都不合格**：

| 键 | 内容类别 | 约束 |
|---|---|---|
| `card_file` | 卡的文件名（**只写文件名，不含目录**）与 | 必须属于下文「卡文件名白名单」 |
| `card_section` | 章节号 | 1–40 字符；允许中文、字母数字、`§ # . - · （）() 、 : ：` 与空格 |
| `type` | 卡点类型 | 枚举四选一：`字段缺`／`表述歧义`／`门不清`／`缺外部信息` |
| `summary` | 一句抽象描述 | 去掉首尾空白后 1–80 字符；单行；不得命中黑名单 |
| `skill_version` | 技能版本号 | 严格 `X.Y.Z` |

日志文件是一串这样的记录（YAML 序列），不设编号、时间戳、作者、会话 id 等其它字段——需要追踪记录归属时，由部署侧在**日志文件之外**管理，不写进记录。

`card_file` 白名单（只列文件名）：`SKILL.md`、`S1-repro.md`、`S2-localize-fix.md`、`S3-verify.md`、`repro.md`、`failing-test.md`、`fix-patch.md`、`verify-log.md`、`validate.py`、`V09-checklist.md`、`README.md`、`PACKAGING.md`。新增卡时同步扩白名单，否则一律判不合格。

## 禁止内容

`card_section` 与 `summary` 一律禁止（`card_file` 由白名单约束，天然不含目录、路径与域名）：

- 代码片段：反引号、代码块围栏、花括号、分号、箭头、赋值表达式、常见代码关键字；
- 路径：`/`、反斜杠、`~`；
- 仓库名与 URL：`://`、`git@`、`owner/repo`（由斜杠规则覆盖）；
- 主机名与内部地址：带 `.local`／`.internal`／`.corp`／`.lan`／`.home`／`.intra` 后缀的域名、`localhost`、IPv4、IPv6、`:端口`；
- 账号与凭证：邮箱样式、`user@host`、16 位以上十六进制串、32 字符以上连续令牌样式串。

## 可机器校验的黑名单

实现见 `validators/check_blocker_log.py`；下表是它的规则源，改动须同步两处。

| 规则 | 正则（Python `re`） | 命中即不合格 |
|---|---|---|
| 代码反引号 | `` ` `` | 是 |
| 代码块围栏 | `~{3,}` | 是 |
| 花括号／分号／箭头 | `[{};]|=>|->|::` | 是 |
| 赋值表达式 | `\b[A-Za-z_]\w*\s*=\s*\S` | 是 |
| 代码关键字 | `\b(def|class|function|import|from|return|SELECT|INSERT|UPDATE|DELETE|CREATE|#include|package)\b` | 是 |
| 路径分隔符 | `[/\\~]` | 是 |
| URL／SSH／邮箱 | `://|\bgit@|[\w.+-]+@[\w.-]+` | 是 |
| IPv4 | `\b\d{1,3}(?:\.\d{1,3}){3}\b` | 是 |
| IPv6 | `\b(?:[0-9a-fA-F]{1,4}:){2,}[0-9a-fA-F]{1,4}\b` | 是 |
| 内部域名后缀 | `\b[\w-]+\.(?:local|internal|corp|lan|home|intra)\b`（忽略大小写） | 是 |
| localhost | `\blocalhost\b`（忽略大小写） | 是 |
| 端口 | `:\d{2,5}\b` | 是 |
| 长十六进制／令牌 | `\b[0-9a-fA-F]{16,}\b|\b[A-Za-z0-9_-]{32,}\b` | 是 |

## 机器判不了的部分（只能人判）

- **不带点的仓库名／主机名／账号**（如 `myrepo`、`build01`）与黑名单不冲突时机器放行；
- 描述是否真的「抽象」——把内部术语、业务名、人名塞进一句话，机器无法识别；
- 记录是否诚实（是否为了留下记录而编造卡点）。

因此**机器校验通过 ≠ 可提交**。默认不上传；提交前必须由人逐条读一遍，再决定是否进入回流汇总。

## 判定与退出码

```bash
python3 validators/check_blocker_log.py <blocker-log.yaml>
```

| 情况 | 结果 | 退出码 |
|---|---|---|
| 文件不存在，或文件为空／只有注释 | 输出「未记录」，**不判 fail** | 0 |
| 任一记录违反本 schema | 逐条列出问题 | 1 |
| 全部记录合格 | 输出条数与「机器校验通过；仍需人判」 | 0 |

「未记录」按约定不是失败；它只表示这次没有可用的卡点数据，统计时必须与「记录了 0 条」区分开。
