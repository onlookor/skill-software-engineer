# V09 人工清单：根因陈述

> 唯一人工项。自动检查判不了的只有一件事：`localization.md` 的根因陈述与 `evidence_kind` 是否**成立**。
> 复核人按本清单人工执行并另留记录；仓内字段不构成复核证据，`status: fixed` 会被 V08 直接拒绝。自动检查阶段状态保持 `fixed_unverified_root_cause`。

## 复核对象

- `localization.md`（机制断言、证据、`evidence_kind`）
- `repro.md`（`under_test` 声明的入口是否就是用户报障的入口）
- `fix.patch`（`touched_files` 与 diff 行数）
- `verify.log`（S3 三段证据）

## 清单

| # | 检查项 | 判定口径 | 签字 | 证据指针 |
|---|---|---|---|---|
| 1 | `evidence_kind` 与证据强度相符 | `direct` 必须能在日志／栈中直接指出成因语句；无此证据只能是 `indirect` 或 `hypothesis` | ☐ | |
| 2 | 机制断言说的是机制，不是表层现象 | 断言对象是异常类型／返回码／状态字段等机制层可观察量 | ☐ | |
| 3 | 成因与失败测试断言同源 | 修复的机制与失败测试断言的机制是同一个 | ☐ | |
| 4 | 最小性对照一致 | `touched_files` 数与 diff 行数符合 `localization.md` 预估；不一致时 V06 已判 fail，须按实际重写 `localization.md` | ☐ | |
| 5 | 第③段反向删证成立 | 撤销补丁后复现复败；并用 `cache_cleanup_policy` 与 `test_command_used` 核对缓存与构建产物复用已被排除 | ☐ | |
| 6 | 无冒充措辞 | `hypothesis` 下未出现「根因已确认／彻底修复／问题已解决」；状态未写 `fixed` | ☐ | |
| 7 | 成因唯一性未被宣称 | 报告没有把「该输入下失败消失」说成「根因唯一」 | ☐ | |
| 8 | 预言与被测代码独立 | 复现测试的期望值不能来自被测函数自身、也不能只断言补丁新加的标记／常量；只能使用 `repro.md` 的 `under_test` 声明的入口，不得读 `calc.EXPECTED`、`add._se_fixed` 或靠 `hasattr` 探测。V03／V08 能拦住静态可见的越界，但动态拼接属性名等仍判不了；变异检验只能证明「测试对补丁行敏感」，不能证明断言是对的 | ☐ | |

## 结论

- [ ] 全部通过 → `localization.md` 的根因陈述成立，`fix-report.md` 可按其 `evidence_kind` 记状态。
- [ ] 任一项不通过 → 状态只能 `fixed_unverified_root_cause`；写明不通过项与原因。不要用 `v09_signoff` 等仓内字段代替人工记录。

## 本清单判不了的部分

- 成因是否为唯一解：不做自动化承诺，也不做人工承诺；只做状态降级与措辞封禁。
- 「补丁是否最小」没有判定标准：只核对数量一致性，不判最优性。
