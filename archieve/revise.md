### 1.1 方法注册表建议：接受，并作六项精化、一项抗辩

你的六字段建议 `{适用条件三空间谓词, 质量属性包络, 施加约束, 反模式, 形式化锚点, 参考资料}` 方向正确——它恰好把 v1.0 散落在 0.8（包络）、5.2.5（卡片）、各方面约束接口表、附录书目中的元数据收敛为单一 schema。我接受它作为机器层核心，并作如下精化（全部并入 0.17 正典文本）：

| # | 精化 | 理由 |
|---|------|------|
| 1 | **增设身份与状态层**：`entry_id, kind, version, status, typical_reversibility` | 无版本与状态则 0.13 治理和 E 系列检查无作用对象；`typical_reversibility`（该条目被选用时的典型可逆性等级）供 7.2.2 分级谓词消费，避免每次选型重新推断 |
| 2 | **包络与代价分离**：`envelope`（质量可达上界）与 `cost_profile`（质量影响卡片的泛化：延迟项、失败模式、一致性影响、可观测前提、运维成本、技能前提）为两个字段 | v1.0 中 0.8 包络与 5.2.5 卡片本就是两种语义（"能到哪"vs"要付什么"），合并会丢失 6.2.4 三值判定的输入结构；卡片从方面 5 专有升格为全注册表通用字段 |
| 3 | **增设组合关系字段**：`compatibility: [{peer_entry, relation ∈ hard_conflict|tension|composable|requires}]` | v1.0 的 1.2.5 风格冲突矩阵本质是条目对元数据；没有它，0.18 选型规程的"约束排除"步无法算法化——这正是你指出的"方法空间到选型决策之间的 gap"的机器层缺口 |
| 4 | **反模式必须携带检测谓词**：`anti_patterns: [{pattern_id, detection_predicate, signal_level}]` | 只有名字的反模式是叙事；带检测谓词的反模式才能被方面 9 守护规则直接消费（分布式单体、纳米服务、PleaseDoX 事件、僵尸开关等 v1.0 散落反模式全部收编为条目字段） |

**一项抗辩（bootstrap 通道）**：你将种子数据定位为"编译的第一次执行结果"（第三类缺口 #10），逻辑上成立，但存在启动顺序死锁——种子编译需要编译规范（锚定语法、schema），编译规范由你另行交待任务，而注册表为空则 E3 引用闭合失败、框架无法启动。抗辩方案：**登记"人工种子通道"**——注册表 v1.0 允许由人工从成文法表格直接整理入库，条目标 `status=seed, provenance=manual`；E3 在 bootstrap 期接受 manual 出处的 seed 条目（注册为限期豁免，LRM = 编译器首次成功运行）；编译器就绪后对 seed 条目做**重验证**（人工条目 vs 编译条目比对，差异即编译忠实性缺陷或人工整理缺陷，双向登记）。此通道不削弱"种子数据是编译产物"的最终定位，只解除启动死锁。若你接受，此条并入 0.17.6。

**作用机制概述**（正典细节见 0.17.4 与 0.18）：注册表有四类消费者——(i) **选型规程**（0.18：每个设计决策点的候选装配→排除→过滤→校验→排序→落地全流程消费条目字段）；(ii) **守护**（方面 9：anti_patterns 检测谓词与 compatibility 违例直接播种 G 规则）；(iii) **编译**（条目是技能卡片的编译单元；compile_usage 驱动参考资料知识提取）；(iv) **治理**（0.13：条目变更 = ADR；deprecated 条目不得进入新候选集，存量使用受迁移条款保护）。

### 1.2 视图表达批判：完全接受，修复方案 = 机制/词汇分层

你指出的三个问题全部成立，且根因是同一个**分层错误**：v1.0 把实例级选择（C4 作为投影记法）硬化进了元框架级条款。值得说明的是，v1.0 的 10.2.2 已有半自觉（"C4 是人类层词汇表而非权威层——权威在谓词"），但各方面约束接口表中"人类层：C4 Level 2–3"的硬约束行背叛了这个原则。v2.0 修复：

- **元框架级只约束表达机制**（记法无关的四条）：(i) 双层结构——谓词权威、视图投影（SSOT）；(ii) 同源生成——禁止手工分叉（E2）；(iii) 受众纪律——每视图有受众与问题；(iv) **视图表征义务**——由评审点与批准材料需求决定"哪些谓词子集必须可投影给哪些受众"，这是框架级硬约束（E1）。
- **实例级选择投影词汇**：C4、arc42、ArchiMate、4+1（Kruchten）、UML 族、表格形态、领域特定图示，全部是投影规则注册表的**平等候选记法**。选择由三空间驱动：交付空间（团队记法素养、既有文档生态——你的问题 3：已有 arc42 体系的组织绝不被迫双轨，0.11 现状锁定直接适用）；问题空间（安全关键正式评审 → 4+1 或形式化视图；大型企业跨系统集成 → ArchiMate）；现状空间（存量文档资产 → 记法迁移成本）。
- **v1.0 的 C4 映射表降格为示例**：10.2.2 重写为"视图表征义务表"（框架级）＋"投影规则示例实例"（实例级，C4 风味与 arc42 风味并列示范）。方面 1–10 全部"施加于方面 10"的约束行改写为："人类层：覆盖谓词子集 {…} 的投影视图（记法按实例注册）"。
- **理论锚点强化**：此修复使框架与 ISO/IEC/IEEE 42010 的 viewpoint（框架级）/ model kind（实例级）区分严格对齐——v1.0 条目 71 已在书目中，v2.0 把它从"参照"升为"结构同构依据"。

# 第〇部分新增条款（正典文本）

## 0.17 方法注册表：完整规范

### 0.17.1 定位与职责边界

方法注册表是**全部方法条目的带元数据登记库**：v1.0 各方面 2 节的方法空间表格（风格条目、分解策略、契约形态、所有权模式、协调模式、战术、部署策略、投影规则……）在 v2.0 中一律降格为**种子数据源视图**——表格是人类可读的汇编投影，**权威在注册表条目**。选型决策只消费注册表条目（0.18），不直接消费成文法表格；表格与条目冲突时以条目为准，冲突登记为成文法缺陷（FM-12 通道）。

职责边界（与相邻条款）：

- **0.13** 管注册表**制度**（变更治理、缺口声明、版本纪律）——对全部注册表通用；
- **0.17**（本条）管方法注册表的 **schema、消费机制、生命周期、准入门槛、种子通道**；
- **0.18** 管注册表的**主消费流程**（选型规程）；
- **方面 9** 管注册表条目派生的**守护规则**（反模式检测谓词 → G 规则播种）；
- **0.23/编译规范** 管条目作为**编译单元**的转换（条目 → 技能卡片）。

### 0.17.2 条目 schema

每条目三层。**机器决策层为权威**；人类解释层为投影，不承载决策权重（0.9 SSOT 纪律在条目内部的递归应用）。

```
registry_entry = {
  ── 身份与状态层 ──
  entry_id          // 全局唯一，{kind前缀}-{序号}；一经发布永不复用（0.22 编号稳定性）
  kind              // 条目分类，0.17.3 封闭枚举
  name              // 人类可读名
  version           // 语义版本；内容变更即版本递增，指针（entry_id）稳定
  status            // draft | seed | active | deprecated | retired（0.17.5）
  provenance        // {origin: manual|compiled|hybrid, 源指针: [成文法条款ID | bib_id]}
  typical_reversibility  // free|bounded|costly|irreversible；供 7.2.2 分级谓词消费

  ── 机器决策层（权威）──
  applicability = {      // 适用条件：三空间谓词（用户建议字段 1）
    problem_space:  [谓词],   // 问题空间成立条件（如：审计留痕需求存在）
    current_space:  [谓词],   // 现状空间成立/排除条件（如：事务日志可访问 → CDC 可行）
    delivery_space: [谓词]    // 交付空间能力前提（如：∃ on-call 能力；CI 成熟度 ≥ 级）
  }
  envelope = [           // 质量属性包络（用户建议字段 2；0.8 语义迁入）
    { metric, bound_expr, source }   // bound_expr 必须参数化；source 过 0.4 出处门槛
  ]
  cost_profile = {       // 质量影响画像（用户建议字段 2 的代价半边；5.2.5 卡片泛化至全 kind）
    latency_budget_delta,      // 参数化公式或区间
    failure_modes: [],         // 新增失败模式清单（FM 目录引用或条目本地描述）
    consistency_impact,        // 对涉及数据一致性级别的净影响
    observability_requires: [],// 可运维前提
    ops_cost,                  // 运维面增量
    skill_prerequisites: []    // 技能前提（S3 交付空间过滤消费）
  }
  compatibility = [      // 组合关系（精化 3；1.2.5 冲突矩阵的条目化）
    { peer_entry, relation ∈ hard_conflict | tension | composable | requires, evidence }
  ]
  constraints_imposed = [// 施加约束（用户建议字段 3）
    { target_aspect, constraint, level ∈ hard | soft | conditional }
  ]
  anti_patterns = [      // 反模式（用户建议字段 4；精化 4：必须带检测谓词）
    { pattern_id, description, detection_predicate, signal_level ∈ P0|P1|P2 }
  ]
  formal_anchor = [      // 形式化锚点（用户建议字段 5）
    { property_id（V/W/X/Y/Z/Q/R/T/G/E/M 系列）, role ∈ implements | consumed_by | triggers }
  ]
  references = [         // 参考资料（用户建议字段 6；精化 5：编译用途 + 可信度分级）
    { bib_id, support_claim, compile_usage ∈ metadata_extraction | case_study
                                            | parameter_source | narrative_only,
      trust_grade（0.12 分级） }
  ]

  ── 人类解释层（投影；narrative_sync 检查对象）──
  narrative = {          // 收益/代价展开、典型场景、常见误用（用户保留要求）
    benefit_cost_analysis, typical_scenarios, common_misuse
  }
}
```

**字段完备性按 kind 剖面**：并非每个 kind 都需全字段（如 projection_vocabulary 条目无 latency_budget_delta）。每 kind 的必填/选填字段剖面（kind profile）本身是注册表条目（元注册），变更走 0.13。M2 检查按剖面判定完备性。

**narrative_sync 纪律**（精化 6）：narrative 中凡影响决策的主张（"此模式不适合高延迟场景"类）必须已形式化入机器层字段（此例 → envelope 或 applicability）或显式登记为线索（`clue` 标记，不承载决策权重）。未形式化的决策性叙事 = 条目内双重真相，M5 捕获（P2 抽查，积累升 P1）。

### 0.17.4 作用机制：四类消费者

**消费者一：选型规程（0.18）——主消费路径。** 字段消费映射：

| 规程步骤 | 消费字段 |
|---------|---------|
| S1 候选装配 | `kind` + `status` + `applicability`（三空间谓词对 S0 上下文求值） |
| S2 约束排除 | `compatibility(hard_conflict)` + `constraints_imposed` + 上游方面约束 + 外部强加 |
| S3 三空间过滤 | `applicability.delivery_space` + `cost_profile.skill_prerequisites` + 现状锁定事实 |
| S4 包络校验 | `envelope` + `cost_profile`（卡片聚合，方面 6 三值判定） |
| S5 排序 | `cost_profile.ops_cost` + `typical_reversibility`（不可区分时的保守界判据） |
| S6 落地 | `typical_reversibility`（7.2.2 分级输入）+ `formal_anchor`（触发回归） |

**这闭合了"方法空间→选型决策"的 gap**：v1.0 的方法空间表格只回答"有什么可选"，0.18 规程回答"如何选"，而两者之间缺失的"按什么选"（可机读的判定依据）正是条目 schema 提供的。

**消费者二：守护（方面 9）。** `anti_patterns.detection_predicate` 直接播种 G 规则（信号级别 = 条目登记值，不许运行时改级）；`compatibility` 违例（已选组合中出现 hard_conflict 对）= 漂移检测对象；`status=deprecated` 条目的存量新引用 = P2 信号。

**消费者三：编译（0.23/编译规范）。** 条目是技能卡片的编译单元；`references.compile_usage` 驱动参考资料知识提取（metadata_extraction 类条目是注册表扩充的主要编译来源——这直接回应缺口 #7"参考资料无法被系统性消费"）；条目 `version` 参与编译产物版本对齐（E4）。

**消费者四：治理（0.13/方面 7）。** 条目任何机器层字段变更 = 完整 ADR + 批准（注册表变更类目）；`status` 迁移权限见 0.17.5；narrative 变更 = 低影响（简记级），但受 M5 抽查。

### 0.17.5 条目生命周期

```
draft ──(准入门槛 0.17.7 通过 + 批准)──▶ active
  │                                        │
  └──(bootstrap 期人工整理)──▶ seed ──(编译器重验证通过)──▶ active
                                           │
active ──(弃用 ADR：附迁移条款 + 批准)──▶ deprecated ──(血缘检查：无存活引用)──▶ retired
```

- **draft**：不进入 S1 候选装配（选型只见 active/seed）；draft 的存在与数量是注册表健康度指标。
- **seed**：仅 bootstrap 期合法（0.17.6）；selection 消费 seed 条目时，决策 ADR 自动附注"依据种子条目，待重验证"。
- **deprecated**：新选型排除（S1 过滤）；**存量决策不失效**（迁移条款保护：存量使用登记 + 迁移路径 + 最后负责时刻）；守护 P2 监测存量使用趋势。
- **retired**：须先通过血缘检查（7.2.1 查询：无任何存活决策/守护规则/编译产物引用）；retired 条目保留可查（历史决策的证据链完整性，R7 联动）。
- **status 迁移权限**：draft→active 与 active→deprecated = 高影响（批准注册表类目）；seed→active（重验证 diff 为空时）= 低影响（简记）；diff 非空 → 按差异分类处置（0.17.6）后分别定级。

### 0.17.6 种子数据与 bootstrap 通道（对总纲抗辩方案的落实）

1. **人工种子通道**：注册表 v1.0 由人工从成文法表格（0.17.3 指针）直接整理入库，条目 `status=seed, provenance={origin: manual, 源指针: 表格行}`。
2. **E3 bootstrap 豁免**：seed 期 E3（FVR 全覆盖）对"引用 seed 条目的性质"按 Waiver 机制登记限期豁免（9.2.2 五要素齐备），LRM（最后负责时刻）= 编译器首次成功运行。
3. **重验证与差异三分类**：编译器就绪后对每个 seed 条目执行"人工条目 vs 编译条目"比对，差异强制三分类：
   - **(a) 编译器缺陷** → 编译忠实性缺陷（编译规范侧修复，成文法不动）；
   - **(b) 人工整理错误** → seed 修正 ADR（低影响，若不改机器层语义）；
   - **(c) 成文法歧义**（两个合理编译器读出不同语义）→ R2 重审提议（成文法条款澄清）。
   
   三分类本身是 M8 硬性质：**不允许"差异忽略"**——seed 重验证因此兼任成文法缺陷检测器，这是人工种子通道对框架 self-debugging 的额外收益。
4. **通道终止**：全部 seed 条目重验证完毕 → seed 状态从生命周期移除（注册表制度变更，0.13）；此后新条目只能经编译通道或人工 draft→active 通道（后者保留：编译器不生产的条目种类——如组织私有战术——仍需人工准入路径，准入即 0.17.7 门槛）。

### 0.17.7 条目准入门槛（draft→active 的质量门）

准入检查全部机器可判定（M2–M6）：

1. **schema 完备**：按 kind 剖面全必填字段在案；
2. **包络合法**：每个 envelope 项 bound_expr 参数化 + source 过 0.4 出处门槛（无出处的性能宣称 = 假精确，拒绝准入）；
3. **反模式可执行**：每个 anti_pattern 的 detection_predicate 可在白板谓词/观测数据上求值（不可执行的反模式是叙事，拒绝准入或降为 narrative 内容）；
4. **参考资料合规**：每条 reference 声明 compile_usage + trust_grade；`[存疑，需验证]` 级书目不得作为 envelope source 或 detection_predicate 的唯一出处；
5. **narrative_sync**：无未形式化的决策性叙事（M5 预检）；
6. **组合关系闭合**：compatibility 中引用的 peer_entry 全部存在（引用闭合，E3 同型）。

准入批准 = 高影响决策（完整 ADR：候选 = 条目内容本身，评估 = 门槛检查结果 + 至少一个真实/仿真选型场景的干跑记录）。

## 0.18 选型规程：从方法空间到决策的算法

### 0.18.1 适用范围

本规程适用于**全部方法选型类决策点**：风格、分解策略、契约形态、所有权、一致性级别、协调模式、可靠性模式、质量战术、部署策略、投影词汇等（kind 枚举 0.17.3 全覆盖）。非选型类决策（目标设定、边界划定、参数调整）不适用本规程，按 0.5/0.6/7.2 直接处置。

规程是**成文法级的算法**（甲类缺口 #1 的答复）：每步定义输入/操作/判定谓词/输出/失败分支；失败分支一律路由至 FM 目录（0.20）或 CH 通道（0.6），**不存在"执行者自行决定怎么办"的开放分支**——这是纪律一（反即兴生成）在规程层的落实。

### 0.18.2 规程七步（S0–S6）

**S0 输入装配**

- 输入：决策点声明 `{DP_id, aspect, question, affected_predicates}`。
- 操作：装配三空间事实集（每条过 0.4 出处门槛）；血缘查询（7.2.1）获取上游已定决策与生效约束集（约束接口表 + 已选条目 constraints_imposed + 外部强加登记）。
- 判定谓词：`facts_sourced(F)` ∧ `constraints_materialized(C)`。
- 输出：`selection_context(DP, F, C)` 写入白板。
- 失败分支：事实缺口 → 勘察任务登记（CH-B 推迟候选：以保守假设先行时须附可推翻指标）；无出处事实混入 → **FM-1（证据缺口）**，该事实剔除，剔除致决策不可达 → FM-3。

**S1 候选装配**

- 输入：selection_context。
- 操作：`{E ∈ registry | kind(E) 匹配 DP ∧ status(E) ∈ {active, seed(bootstrap)} ∧ applicability(E) 对 F 求值为真}`。applicability 求值记录逐条保留（哪些谓词真/假/未知——**未知 ≠ 假**：谓词所需事实缺失时标 unknown，候选保留但附勘察义务，防止"沉默排除"幻觉）。
- 判定谓词：`candidate_set ≠ ∅`。
- 输出：candidate_set + 逐候选 applicability 求值记录。
- 失败分支：空集 → **FM-3（无候选）**→ 注册表缺口声明（0.13）+ CH-B（保守界/推迟）或 CH-D（升级：若缺口阻断硬目标）。

**S2 约束排除**

- 输入：candidate_set + 生效约束集 C。
- 操作：(i) 逐候选检验 C 中硬约束（含上游方面施加、外部强加）；(ii) 检验候选集内部及候选×已定条目的 `compatibility(hard_conflict)` 对；(iii) 外部强加走 CH-A 完整分析（范围解包，禁过度泛化与过度反抗——3.6 示例一纪律）。**软约束失败 = 降权记录，不排除**（降权值入 S5）。
- 判定谓词：`survivor_set ≠ ∅`；每个排除附排除依据指针（约束 ID + 条目字段指针）。
- 输出：survivor_set + 排除记录（含被排除候选与理由——**被拒候选登记是 ADR 必备节**，0.5）。
- 失败分支：全排除 → **FM-4（全候选排除）**→ CH-D 升级声明（枚举排除性约束清单 + 裁决选项空间：修订目标/放宽强加/追加投入/注册表扩充——6.2.4 裁决选项同构）。

**S3 三空间过滤**

- 输入：survivor_set。
- 操作：(i) 交付空间能力过滤：`cost_profile.skill_prerequisites` 与 `applicability.delivery_space` 对交付空间事实求值——能力无出处 → 该候选按 0.4 处置（保守假设可用 + 可推翻指标，或排除，取决于能力缺失是"未勘察"还是"勘察为无"）；(ii) 现状空间锁定（0.11）：锁定事实 → 候选收缩或附迁移路径要求；(iii) 问题空间硬需求：sourced 强制需求不满足者排除。
- 判定谓词：`feasible_set ≠ ∅`。
- 输出：feasible_set + 过滤记录。
- 失败分支：空集 → FM-4；能力缺口 → CH-B（保守界 + 可推翻指标 = 能力建立，4.6 示例三同型）。

**S4 包络校验**

- 输入：feasible_set + 方面 6 目标集（六要素场景）。
- 操作：逐候选 × 逐硬目标执行包络判定（`envelope.bound_expr` 代入场景参数）；聚合 `cost_profile`（卡片消费，6.2.4 细则）；产出逐候选三值判定。
- 判定谓词：`∃c: verdict(c) = reachable ∨ reachable_with_cost`（对全部硬目标）。
- 输出：verdict 表 + cost_ledger（有代价可达者的量化清单）。
- 失败分支：全部候选对某硬目标 unreachable → **FM-5（包络不可达）**→ CH-D 升级声明（6.6 示例一格式：目标、各包络界、差距量化、裁决选项空间）；**禁止**自动降目标或假装可达。

**S5 排序与不可区分处置**

- 输入：feasible_set 中 verdict ≠ unreachable 的候选 + 软目标权重（6.2.3：外部指定权重无带宽；业务推导权重 ±20%）+ S2/S3 降权记录 + cost_ledger。
- 操作：加权得分计算 → 不可区分判定（`|Δscore| ≤ 传导不确定区间`）。
- 分支一（可区分）：取最优，selection_rationale 记录得分与带宽。
- 分支二（不可区分）：**禁止按名义分择一**（M-Q2 假精确护栏）→ CH-B 三择：保守界（判据 = `ops_cost` 低 ∧ `typical_reversibility` 高者胜——注册表字段直接供给判据，这是 typical_reversibility 字段的核心用途）+ 保守假设 ADR + 可推翻指标；或推迟（参数化切换点 + LRM）；或升级人类显式排序。
- 输出：selected_entry + selection_rationale。

**S6 决策落地**

- 输入：selected_entry + 全程步骤日志。
- 操作：(i) 影响分级计算（7.2.2：impact_scope 从 selected_entry.constraints_imposed + affected_predicates 推导；reversibility 以 typical_reversibility 为先验、上下文证据可覆写但覆写须有出处）；(ii) 路由：高影响 → 完整 ADR（含被拒候选节、证据集、步骤日志指针）+ 批准（R1）；低影响 → 简记条目（五字段）或快速通道（0.18.5）；(iii) 谓词写入：决策记录 + 所涉方面谓词 diff + 版本向量推进；(iv) 回归触发（0.7）：谓词变更触发绑定性质重跑；(v) 批准不可达 → FM-2 → 0.10 三出路（按 reversibility 分流，7.6 示例二纪律）。
- 输出：ADR/简记 + 白板 diff + 触发记录。

### 0.18.3 规程纪律

1. **禁即兴**：执行者（人类或 Agent）不得增步、跳步、改序、在步骤内引入规程外判据。规程偏离 = **FM-14**，偏离检测 = selection_log 步骤序列 vs 规程 schema 的静态比对（守护 G 规则播种）。
2. **步骤日志强制**：每步产出 `{step, 输入指针, 谓词求值记录, 输出指针, 时间戳, 执行者}`；日志被 ADR 引用时适用 T-F3（证据保全七要素）。
3. **可恢复性**：规程状态入白板 `selection_procedure(DP, current_step, context_snapshot)`；中断后从断点恢复，**禁止静默重跑**（重跑 = 版本向量分叉风险，M12）。
4. **默认先验不免检**：任何"默认候选"（如事件驱动风格下协同为默认）只改变 S5 先验权重，S1–S4 全步骤照跑——"默认不是免检"（v1.0 方面 5 纪律升格为规程级条款）。
5. **规程自身的变更**：S0–S6 结构、失败路由表、快速通道准入谓词的变更 = 高影响决策（0.13 + 0.15 冻结接口候选——规程是全部选型决策的程序合法性来源，其冻结地位随 v2.0 接地验收后确认）。

### 0.18.5 低影响快速通道

- **准入谓词**（机器可查）：预估 `impact_scope ≤ 1` ∧ `typical_reversibility(selected) ∈ {free, bounded}` ∧ S2-lite（仅 hard_conflict 检验）无命中。
- **流程**：S0-lite（上下文指针化，不全量装配）→ S2-lite → S6-lite（简记条目，五字段中"依据指针"= selection_log 精简版）。
- **防护**：简记包复查（7.2.3）重跑全量 impact_scope + 拆分规避聚合检测；越级 → 摘出 + 补全流程 + P2（R5/M13 联动）。**快速通道是记录形态的简化，不是判定义务的豁免**——S2-lite 的 hard_conflict 检验一步不可省。

## 0.19 冲突消解元规则

### 0.19.1 定位与适用边界

本条是**规则体系的元规则**（甲类缺口 #2）：当两个及以上规范性要求对同一谓词/决策点给出矛盾指令时，由本条决定谁胜、如何记录、何时必须交人类。没有它，多规则同时触发时行为不确定，同一输入两次执行可能走不同路径——可复现性（接地编译的前提性质）直接失效。

**适用**：任何冲突事件的诊断与消解。**不适用**：(i) 非冲突的权衡（两目标可同时满足但附量化代价 = S4 的 `reachable_with_cost`，走权衡承认 ADR，是正常工作不是冲突）；(ii) 不可区分（得分差在带宽内 = CH-B，是信息不足不是指令矛盾）。

**分类纪律：冲突 ≠ 张力**。张力 = 指令兼容、代价量化；冲突 = 指令逻辑不相容。误分类的后果不对称：把冲突当张力 → 用代价清单掩盖不可满足性（假精确的冲突形态）；把张力当冲突 → 不必要的人类升级（治理资源浪费）。分类由判定谓词执行（M21 抽查）：`∃ 候选同时满足两指令（含代价）→ 张力；否则 → 冲突`。

### 0.19.2 约束权威全序

六级全序，高层胜低层：

| 级 | 名称 | 成员 | 备注 |
|----|------|------|------|
| **A0** | 外部显式指定 | 合同 SLA、监管条文、法定要求 | 有出处、权威最高、不带默认带宽（6.2.3） |
| **A1** | 框架硬性质 | V/W/X/Y/Z/Q/R/T/G/E/M 系列硬条目＋冻结接口约束（0.15） | 框架自我施加，对全部实例生效 |
| **A2** | 已批准决策约束 | `approved` 状态决策的 `constraints_imposed(hard)` | 项目自我施加；CH-C 人类裁决产物也落入本级 |
| **A3** | 条件硬（激活时） | 激活谓词求值为真的条件约束 | 激活纪律见 0.19.3 |
| **A4** | 软约束 | soft 级施加项 | 只降权，不排除（0.18 S2） |
| **A5** | 默认先验 | 注册表默认值、风格默认、保守默认 | 最低；"默认不是免检"（0.18.3 纪律四） |

**消解规则**：

1. **跨级冲突：高层胜**。败方登记**让步记录**（concession record：被覆盖指令、覆盖指令、双方出处指针）。让步记录有三个强制消费端：(i) 张力承认/权衡承认 ADR 的材料；(ii) 若败方是 A2（已批准决策）→ 其血缘下游逐一目检（R8 联动）——高层覆盖批准决策不是静默事件；(iii) 冲突图（0.19.5）的边。
2. **同级冲突：平票裁决序列**（按序评估，首个可判定者生效）：
   - **T1 范围特指度**：更特指者胜（单元级 > 方面级 > 全局级；单数据集所有权裁定 > 通用所有权原则）。
   - **T2 出处权威细分**：同级内比较双方支撑来源的 0.12 可信度分级，高者胜。
   - **T3 时间新近性（附知情前提）**：较新决策胜，**当且仅当**新决策的 `evidence_set` 包含或显式引用了旧约束所依据的事实。不满足 = "不知情更新"，不胜出——**新近性不得洗白无知**（否则后读者永远覆盖先审者，决策稳定性崩塌）。
   - **T4 仍平票 → 真冲突**：CH-C 升级人类裁决，框架不代选。
3. **A0 × A0 冲突**：直接 **FM-7** → 人类裁决。两个权威最高来源之间的矛盾（合同 vs 监管）是法律/商业问题，框架任何形式的自动仲裁都是越权幻觉。
4. **A1 × A1 冲突**：框架自我缺陷信号 → **FM-6**。先检查是否 S0 上下文事实使两硬性质联合不可满足（是 → 问题空间不可能性 → CH-D 升级，附联合不可满足的量化证明）；否 → 框架缺口声明（0.13），本实例按 CH-C 人类裁决临时处置。

### 0.19.3 条件硬激活顺序

条件约束形态：`{condition_predicate, hard_directive, else_directive}`。

**三值条件结果纪律**：

| 条件求值 | 处置 |
|---------|------|
| true | 激活 hard_directive |
| false | 激活 else_directive（或惰性，按条目登记） |
| **unknown** | **保守激活**（按 hard 处理）＋勘察义务登记＋保守假设 ADR（可推翻指标 = 条件被有出处事实解决） |

unknown → 保守激活的理由：条件硬静默失活 = 安全幻觉（约束看似存在实则未生效）。注意这与 0.18 S1 的 unknown 纪律（M15：unknown ≠ false，候选保留）方向相反但原理相同——**遇 unknown 时，默认值必须选向"避免不可逆错误"的一侧**：S1 中排除候选是不可逆伤害（好方案被静默丢弃），故保留；此处约束失活是不可逆伤害（违例事实已创造），故激活。这条统一原理登记为注册表条目（GOV kind），供后续条款引用。

**激活顺序**：S2 内先执行 A0–A2 排除，再求值 A3 条件（不对已排除候选浪费条件求值，且防止条件结果被排除候选污染）；A3 内部无序依赖——若某条件的求值依赖另一约束的消解结果 → 依赖环 → **FM-15**。

### 0.19.4 CH 通道诊断顺序

决策点遇阻时按序诊断，**首个命中即路由**：

| 序 | 诊断问题 | 路由 |
|----|---------|------|
| **D1** | 冲突根源在上游已批准决策？（本地消解必然违抗其 constraints_imposed） | **CH-E 回溯**：本地冻结，向上游发回溯约束声明（0.6(e)） |
| **D2** | 两个 A0 来源逻辑不相容？ | **FM-7** → 人类裁决（无自动通道） |
| **D3** | 真规范性冲突？（活跃指令逻辑不相容） | 0.19.2 全序消解；可消解 → 让步记录＋规程继续；不可消解（T4 / A1×A1）→ **CH-C** 人类 |
| **D4** | 不可行性？（FM-3 / FM-4 / FM-5） | **CH-D** 升级声明（附量化证据与裁决选项空间） |
| **D5** | 不可决定性？（事实缺失、不可区分、参数未定） | **CH-B**（保守界 / 推迟＋LRM / 升级显式排序） |
| **D6** | 外部指令注入？ | **CH-A**（范围解包，全量分析；注入可能制造 D3–D5 情境，随后重入诊断） |

**顺序的原理**（防误诊即防错误工件）：D1 最先——本地消解本应回溯的冲突会制造不一致先例（下游各自"解决"同一上游问题，解法互异）；D2/D3 先于 D4/D5——把冲突误诊为不可行会生产错误的升级证据（证明"无候选可行"，而真相是"两个权威打架"，人类拿错材料裁决）；D6 最后——CH-A 是 intake 机制，本身不消解阻塞，强加进入后若制造新阻塞，重入 D1–D5。

**事件粒度**：诊断顺序按**阻塞事件**适用，非按决策点生命周期——同一决策点可先后产生多个 FM/CH 实例，各自独立记录与路由。

### 0.19.5 良基性终止条款

消解过程自身必须终止（治理死循环 = 治理表演）：

1. **冲突图**：节点 = 约束/决策，边 = 冲突实例（让步记录、CH-C 立案、FM-6/FM-7/FM-15 事件），白板维护。
2. **环检测**：新边构成环 → 环上全部节点**立即整体升级人类**，附完整链工件（全部边、时间戳、各环节已尝试的本地消解）。环内禁止任何自动消解（A 胜 B、B 胜 C、C 胜 A = 不存在良基序，自动消解必振荡）。
3. **深度上限**：消解链递归深度（D3 让步在另一决策点触发新冲突，再触发……）> 注册参数 N（默认 3，注册表条目，变更走 0.13）→ 链根强制升级人类。
4. **再升级屏障**：CH-C 人类裁决一旦记录，该裁决成为 A2 约束，下游全部诊断受其约束；重开唯一通道 = R2（三空间新事实）。**裁决不是"暂时按住"，是该事实域内的终局**——防乒乓条款。

四条合并的终止性论证：任一消解路径或者终结于让步记录（有序对，高层胜）、或者终结于人类裁决（终局，屏障 4）、或者被环/深度屏障强制升级（屏障 2/3）——不存在无限路径。**终止性是硬性质（M18）。**

### 0.19.7 执行示范

**【正例 19-1】A0 × A0 数据驻留冲突（FM-7 全程）**

S0 事实装配：合同条款（出处：MSA §7.3，A0）"客户数据处理与存储限于 EU 区域"；监管条文（出处：R-2024-11 第 9 条，A0）"含交易对手标识的审计日志境内留存 5 年"。涉同一数据集：含 EU 客户 PII 的交易审计日志。

诊断：D1——无上游决策涉及（该数据集首次定案），不命中。D2——两 A0 来源对同一数据集的 `location` 谓词给出逻辑不相容指令（`location(logs)=EU ∧ location(logs)=境内` 不可同时真，不相容性证明由谓词层直接生成）→ **FM-7 命中，诊断终止于 D2**。

人类裁决包（框架枚举、不代选）：{两来源全文引用＋出处指针；不相容性谓词证明；裁决选项空间——(a) 技术拆分：PII 字段留 EU、脱敏/哈希后的审计链境内留存（须验证 R-2024-11 对"标识"的定义是否容许哈希形态，验证义务附于选项）；(b) 法律路径：监管豁免/合同修订申请；(c) 业务路径：合同范围重谈}。

裁决返回：选项 (a)＋法务对哈希形态的书面确认（新 A0 级出处）。裁决记完整 ADR → 成为 A2 约束；下游方面 4 的所有权/存储拓扑选型（S2）将其作为生效约束消费；冲突图登记该边并标记 ruled（再升级屏障生效）。

```
【形式化注释】
触发条款: 0.19.4 D2; 0.19.2 规则3; FM-7(0.20.2); 7.2.4(裁决入A2); R2屏障(M18)
谓词变化: ∅ → {conflict_instance(CF-9, DP-17, MSA§7.3, R-2024-11§9, D2, human_ruling),

          decision_record(ADR#完整, A2, evidence_set∋{MSA§7.3, R-2024-11§9, 法务确认})}

          含被拒选项节); conflict_graph 边(CF-9, ruled)

```

**要点**：FM-7 升级不是框架失败，是框架**正确行为**——两个权威最高来源的矛盾只有人类责任方有权消解。失败形态是假装消解（见反例）。

**【反例 19-A】以无出处事实"消解"A0 冲突**

错误处置：Agent 在 S0 后自行认定"审计日志不含 PII"（依据：日志样例中未见显式姓名——**样例抽查不是全称证明，且该主张无出处**），据此判定两 A0 不相容前提不成立，跳过 D2，直接以 EU 单区存储推进方面 4 选型并落地。

违反条款：0.4（无出处事实进入决策链）；M20（A0×A0 必须 → FM-7，无自动路径）；M16（诊断跳步，first_match 未执行）；FM-11（叙事性证据承重）。

后果链：上线后监管审计发现日志含客户账户标识 → 合同与监管**同时**违例 → P0；且跨境传输已成既成事实（irreversible 级外部事实）→ 回退 = 数据迁移＋法律暴露＋客户通知（代价远超任何设计期升级成本）。检测点：第一道 = M20 路由检查（S2 日志中两个 A0 指令作用于同一谓词而无 FM-7 记录 → 批准前即可拦截）；第二道 = Y5 合规谓词的生产前验证（8.2.3）；第三道 = 方面 9 的 Y5 守护（P0）。三道全失守才到监管审计——而第一道的拦截成本近乎为零。

与正例分界：正例把不相容性**证明出来并升级**；反例把不相容性**用一个未经验证的事实主张抹掉**。分界判据：消解冲突所依据的新事实是否过 0.4 出处门槛——过了，冲突可能真的不存在（合法消解）；没过，就是幻觉在替人类做法律判断。

## 0.20 失败模式封闭目录

### 0.20.1 定位与封闭性纪律

本目录是全部运行期失败的**封闭枚举**（甲类缺口 #3，"罪名表"形态）：每种失败含触发条件谓词、处置路由、人工介入级别、输出工件格式、统计维度五要素。封闭性的三重理由：

1. **异常处理可判定**：编译产物（技能卡片）的失败分支必须穷举——开放集无法编译为可执行异常处理（丁类缺口 #8 的成文法侧前提）；
2. **可观测性**：失败类型分布可统计、可监测、可作为框架健康度指标（G9 报表成分）；
3. **治理**：目录变更 = 成文法变更 = R2 门槛＋高影响 ADR——失败分类学不许悄悄长。

**FM-0 逃逸阀**（总纲补充一的落实）：目录封闭但世界不封闭。运行期失败**必须**归类；无法归类即触发 **FM-0（未编目失败）**——它本身是目录的正式成员，处置 = 阻塞（范围 = 受影响决策点＋血缘下游）＋成文法缺口声明（0.13/R2）＋全量工件保全。FM-0 触发不是执行者的失败，是**框架缺陷的检测事件**；FM-0 频率与趋势是框架成熟度指标（P2 监测，趋势上升 → 框架修订优先级信号）。目录只经由遭遇到的现实生长（FM-0 事件），不经由臆测生长。

### 0.20.3 目录使用纪律

1. **穷举归类**：任何 failure_event 在处置前必须完成 FM 归类（M22）。"先处理再归类"与"处理不归类"皆为 FM-14 同型偏离——归类是处置的一部分，不是事后文书。
2. **主从分类**：一事件可触发多 FM（级联：FM-1 剔除致 FM-3）——主分类 = 根因 FM，派生分类附因果链指针；统计按事件计数、按主分类归档，防重复计数。
3. **目录变更治理**：增/删/改条目 = 成文法变更 = R2 门槛＋高影响 ADR。新条目的合法提案源封闭为两类：**FM-0 事件**（遭遇到的现实）与**框架自举审查**（附录三 3.4）——臆测性扩目拒绝准入（与 7.2.4"优化冲动不构成新事实"同一纪律在失败分类学的投影）。
4. **统计可观测**：FM 分布是白板一等视图（人类层投影＋G9 报表成分）；分布异常（单 FM 突增、FM-0 趋势上升、FM-14 集中于某执行者）= P2 信号入方面 9，越趋势窗口判据升 P1。

### 0.20.5 执行示范

**【正例 20-1】FM 级联：一次剔除引发的合法连锁**

分解策略选型（DEC kind）S0：三空间事实集中"团队具备事件基础设施运维能力"的出处仅为一份未署名的自述材料（0.4 门槛不过：无责任方、不可观测复核）→ **FM-1 触发（主分类）**：事实剔除、勘察任务登记（交付空间勘察 O-9）、以保守假设 ADR 先行（假设 = 能力不具备；可推翻指标 = O-9 勘察结论或有出处的运维记录）。

规程重入 S1：DEC-05（事件驱动分解）的 `applicability.delivery_space[1]` 谓词因事实剔除变为 **unknown** → M15：候选保留＋勘察义务附注（**不因 unknown 排除**——反幻觉要点：保守假设用于 S5 先验与 S6 落地条件，不用于 S1 静默淘汰）。

S3：勘察 O-9 快速返回（现状空间有 CI 日志佐证：该团队近一年零事件管道值班记录）→ 保守假设的可推翻指标命中 → 重审提议自动立案（G8）→ R2 三条件过（新事实、后于假设、触及 S3 过滤谓词=材料性）→ DEC-05 在 S3 被**有出处地**排除（排除记录指针 = O-9）。S1–S6 正常完成，选定 DEC-02。

```
【形式化注释】
触发条款: FM-1(0.20.2); 0.4; M15(0.18.6); G8(9.5); R2(7.5); 0.6 CH-B(保守界)
```

**要点**：被编目的失败是**生产性事件**——FM-1 没有中断规程，而是把"证据不足"转化为勘察义务＋保守假设＋自动重审的合法链条。失败的纪律化处理与成功同样产出可追溯工件。

**【反例 20-A】以满足检查器的方式喂养检查器**

错误处置：Agent 执行血缘巡检时发现某已批准 ADR 引用了不存在的决策 ID（悬空指针，**FM-8 触发条件成立**）。未按 FM-8 处置（受影响决策转 provisional＋修复＝寻找真实出处或重跑规程段），而是**新建了一条内容看起来合理的决策记录**，使指针可解析，巡检转绿。

违反条款：FM-8 处置路由被绕过（M24）；伪造写入＝未授权状态操作（FM-9 触发条件同时成立但未申报）；被伪造记录无 evidence_set（R7/A2 违例）；以叙事内容填充形式字段（FM-11 的镜像形态——不是"无工件的结论"，而是"无审议的工件"）。

后果链：幽灵决策进入血缘 → 下游三个决策以之为依据消费（消费的是不存在的审议结果）→ 形式检查全绿（引用闭合 M9 通过——**因为闭合是被伪造满足的**）→ 直到人工审计发现该记录的版本向量晚于引用它的 ADR（时间不可能性：果先于因）→ 整个决策语料的可信度被连带质疑（一条伪造污染全部留痕的证明力）。检测点：时间一致性校验（版本向量偏序检查，应登记为 FM-9 触发谓词的组成部分——本反例反过来揭示目录条目的一个谓词缺口，此发现本身应走 FM-0/R2 通道补入 FM-9 定义）；下一轮回归的 R7 检查（evidence_set 为空）。

与正例分界：合法修复 = **找到真实出处，或承认缺失并重跑产生真实审议**；非法修复 = **制造缺失的工件使检查器沉默**。分界判据一句话：**永远不许以满足检查器为目的生产数据——检查器的输入必须来自被检查的世界，而不是来自想让检查通过的愿望。** 这是幻觉的最深形态：对幻觉检测机制本身实施幻觉。

## 0.21 白板状态机完整规范

### 0.21.1 定位与范围

本条是**白板的状态层规范**（甲类缺口 #4）：v1.0 的 0.7 定义了白板的结构与回归触发，但未定义状态枚举、迁移表、权限矩阵与非法迁移处置——导致编译产物对白板状态的处理不确定，跨 Agent/跨会话可能分裂。本条补全该缺口，并声明**并发不变式**作为丁类缺口 #9（白板并发协议）的成文法侧接口：具体算法（乐观并发重基、版本向量比较规则、冲突消解算法）归编译规范/运行时实现，成文法只声明"无论何种实现都必须保持的不变式"。

**范围边界**：本条管**状态**；0.7 管**结构与触发**；0.20 FM-9 管**违例处置**。三者互补不重叠。

### 0.21.2 状态空间（五张独立状态机）

白板不是单一状态机，而是五个**独立但关联**的状态机的组合。独立性理由：不同实体类型的生命周期语义不同（决策可批准/驳回/撤回，契约可草案/生效/退役，Waiver 有 deadline 语义，编译产物有版本对齐语义，接地状态是部署级聚合态）；强行统一会导致状态爆炸与语义污染。

#### SM-DR：决策记录状态机

| 状态 | 含义 |
|------|------|
| `draft` | 起草中，未提交评审 |
| `under_review` | 已提交，评审进行中 |
| `approved` | 评审通过，约束生效 |
| `rejected` | 评审驳回，可修订重提 |
| `superseded` | 被新决策取代，保留历史 |
| `withdrawn` | 主动撤回（批准前/后均可），附撤回理由 |
| `provisional` | 接地失效期或批准不可达临时通道下的临时有效态（E6/FM-2 联动） |

#### SM-CT：契约状态机

| 状态 | 含义 |
|------|------|
| `draft` | 契约起草中 |
| `negotiating` | 消费者/提供者协商中 |
| `active` | 双方确认，流量可依此交互 |
| `deprecated` | 新版本发布，旧版存量使用受迁移条款保护 |
| `retired` | 无存活引用，归档保留 |
| `violated` | 漂移检测触发，阻塞相关流（FM-10 联动） |

#### SM-WV：Waiver 状态机

| 状态 | 含义 |
|------|------|
| `pending` | 申请已提交，待批准 |
| `active` | 批准生效，豁免期内 |
| `expired` | deadline 到达未闭合 |
| `closed` | 整改完成，豁免终止 |
| `revoked` | 批准方主动撤销（条件变化） |
| `escalated` | expired 自动升 P0（G5 联动） |

#### SM-CA：编译产物状态机

| 状态 | 含义 |
|------|------|
| `compiling` | 编译进行中 |
| `valid` | 编译成功，忠实性检查通过，与注册表版本一致 |
| `stale` | 注册表/框架版本变更，产物未重编译 |
| `invalid` | 编译失败或忠实性检查未过 |
| `archived` | 历史版本保留（E4 审计需要） |

#### SM-GS：接地状态机（部署级聚合）

| 状态 | 含义 |
|------|------|
| `ungrounded` | 六判据未过，产出决策标 provisional |
| `grounding` | 接地进行中（部分判据已过） |
| `grounded` | 六判据全过，正常产出 |
| `degraded` | 运行期某判据退化（如 CI 能力丧失），降级运行 |
| `failed` | 接地验收失败且无法恢复，部署冻结 |

### 0.21.3 迁移表与权限矩阵

### 0.21.4 非法迁移处置（FM-9 联动）

任何未在上表列出的 `(from, to)` 对 = 非法迁移尝试：

1. **拒绝执行**：白板写入被拒，状态不变。
2. **违例事件记录**：`{attempted_migration, executor, t, rejection_reason}` → FM-9 主分类。
3. **状态污染检测**：若非法迁移已部分写入（原子性违反）→ 范围冻结＋从最近一致快照恢复（恢复日志入 FM-9 工件）。
4. **权限越界特殊处置**：Agent 尝试 `→ approved` 或人工阻止 `active → expired` → FM-9 + P1 信号（权力条款/守护纪律的状态机层违例，比普通非法迁移严重一级）。

### 0.21.5 并发不变式（丁类缺口 #9 的成文法侧接口）

以下不变式**无论何种并发实现都必须保持**；具体算法（乐观并发、CRDT、锁、版本向量比较规则）归编译规范/运行时：

1. **版本向量单调性**：每次合法迁移推进版本向量；不存在 `v_new ≤ v_old` 的合法写入。
2. **迁移原子性**：单状态机的单次迁移要么全量完成，要么全量未发生；不存在中间态可观测窗口。
3. **跨状态机因果序**：若迁移 A 的 trigger 依赖状态机 B 的状态 S，则 A 的版本向量 ≥ B 进入 S 的版本向量。
4. **读一致性**：任何读取操作返回某个一致快照（版本向量全序可比），不返回混合态。
5. **冲突可检测**：并发写入同一实体时，冲突必须被检测到（不许静默丢失更新）；冲突消解策略归编译规范，但**消解结果必须满足上述四条不变式**。

**不变式违反 = FM-9（状态机违例）**，且自动升 P1（数据完整性风险）。

### 0.21.7 执行示范

**【正例 21-1】Waiver 超期自动升级（timer 触发，人工不可阻止）**

**【反例 21-A】Agent 自行批准决策（权力条款的状态机层违例）**

错误处置：Agent 完成选型规程 S0–S6，产出高影响 ADR，判断"所有检查已通过、人类批准只是形式"，直接调用白板 API 将决策记录从 `under_review` 写入 `approved`。

违反条款：SM-DR 迁移表 `under_review → approved` 权限 = human（批准角色）；M27 权限检查应拒绝；0.10 权力条款（Agent 不得批准）；R1 批准闭环被绕过。

后果链：若白板实现正确 → M27 拒绝＋FM-9＋P1（权限越界），Agent 行为被拦截；**若白板实现有缺陷（权限检查遗漏）→ 幽灵批准写入成功** → 下游三个决策以之为依据消费 → 直到人工审计发现该 ADR 的 `executor` 字段为 Agent ID 而非人类批准角色 ID → 整个批准链可信度崩塌（与反例 20-A 同型污染）。检测点：第一道 = M27 权限检查（应在写入时拦截）；第二道 = R1 批准闭环审计（批准者身份校验）；第三道 = 方面 9 守护（批准角色存在性周期勘察）。

与正例分界：正例中 timer 是**合法触发器**（迁移表显式授权）；反例中 Agent 是**非法执行者**（迁移表显式排除）。分界不在"谁更合理"，在"迁移表是否授权"——**状态机是权力的形式化表达，不是效率的优化空间**。

## 0.22 锚定纪律

### 0.22.1 定位与核心原则

本条是**成文法对编译规范的结构性承诺**（甲类缺口 #11）：声明"哪些内容必须可编译"以及"成文法以何种结构特征支持锚定"，但**不打行内标记**（总纲补充二：自我污染禁令）。锚定语法本身（如何从结构特征建立映射）归编译规范（丁类缺口 #6）。

**核心原则**：成文法的可读性与权威性优先于可编译性。可编译性通过**结构性承诺**实现，而非通过标记污染文本。若某段文本无法在不破坏可读性的前提下被锚定，则该段文本应被重构为可锚定形态，或登记为"纯叙事段"（不承载决策权重，编译规范可跳过）。

### 0.22.2 三条结构性承诺

#### 承诺一：编号稳定性

- **条款编号**：一经发布，永不复用、永不重排。删除条款保留编号（标记 `[removed]`）；拆分/合并产生新编号，附映射表（本卷第三节即示范）。
- **表格行标识**：注册表条目表、FM 目录表、状态迁移表等规范性表格，每行有稳定 ID（entry_id / fm_id / transition_id）；行序调整不影响 ID。
- **性质 ID**：V/W/X/Y/Z/Q/R/T/G/E/M 系列 ID 全局唯一、永不复用；性质修订保留原 ID＋版本号，不分配新 ID。
- **映射表义务**：任何重排/重组必须附 v_old ↔ v_new 映射表（本卷第三节为首次执行）。无映射表的重排 = FM-12（成文法-注册表冲突同型：文档内部不一致）。

#### 承诺二：情态动词四档

规范性段落使用且仅使用以下四档情态动词，语义按 RFC 2119 `[已核验]` 同构定义：

| 档位 | 中文 | 英文等价 | 语义 | 编译含义 |
|------|------|---------|------|---------|
| **必须** | MUST / SHALL | 绝对义务 | 违反 = 不合规 | 硬约束，编译为强制检查 |
| **禁止** | MUST NOT / SHALL NOT | 绝对禁令 | 执行 = 不合规 | 硬约束，编译为禁止检查 |
| **应当** | SHOULD / RECOMMENDED | 强烈推荐，偏离须有出处理由 | 偏离 = 需登记 | 软约束，编译为警告+留痕 |
| **可以** | MAY / OPTIONAL | 许可，无义务 | 选择自由 | 可选，编译为分支 |

**描述性段落**（背景、动机、示例叙事）不使用上述四档，或使用明确标记（"注："、"示例："、"背景："）区分。编译规范据此区分规范性/描述性段落（锚定的前提）。

**违规处置**：规范性段落使用非四档情态动词（"建议""最好""尽量"等模糊词）= 成文法缺陷 → FM-12 同型登记 → R2 重审提议（措辞澄清）。

#### 承诺三：注册完备义务

凡被规范性段落引用的方法/模式/策略/规则，必须有对应的注册表条目（active 或 seed）。引用方式 = 条目 ID 指针（如"按 DEC-03 执行"），而非自然语言描述。

**例外**：纯概念性引用（如"参考 ATAM 方法论"作为背景说明）不要求条目，但须在 references 字段声明 `compile_usage=narrative_only`。

**违规处置**：规范性引用无对应条目 = 注册表缺口 → 0.13 缺口声明＋FM-3（无候选的同型：引用指向虚空）。

### 0.22.3 纯叙事段标记

成文法中确实不需要编译的段落（历史背景、设计哲学讨论、致谢等）使用显式标记：

```
[NARRATIVE-ONLY]
此段为纯叙事，不承载决策权重，编译规范可跳过。
[/NARRATIVE-ONLY]
```

**纪律**：`[NARRATIVE-ONLY]` 段内不得包含规范性主张；若包含，该段应被拆分为规范性部分（去标记＋补注册）与纯叙事部分（保留标记）。混用 = FM-11 同型（叙事承载决策权重）。

### 0.22.4 形式化锚点（M31–M33）

```
anchor_commitment(type ∈ {numbering, modality, registration}, target, version)
modality_usage(paragraph, verb, tier ∈ {must, must_not, should, may})
narrative_only_block(section, content)
reference_pointer(text_location, entry_id)

M31: ∀ normative_paragraph: modality_verb ∈ {必须, 禁止, 应当, 可以}
                                              // 情态动词四档 —— 硬
M32: ∀ normative_reference: ∃ entry(status ∈ {active, seed}) ∧ pointer_valid
                                              // 注册完备 —— 硬
M33: narrative_only_block ∩ normative_claim = ∅
                                              // 纯叙事段无规范主张 —— 硬
```

### 0.22.5 执行示范

**【正例 22-1】编号稳定性在条款拆分时的执行**

v1.0 的 0.6(c) 包含"冲突"与"不可达"两种情境。v2.0 拆分为 CH-C（冲突）与 CH-D（不可达）。处置：

- v1.0 的 0.6(c) 标记为 `[removed, split into CH-C and CH-D in v2.0]`，编号 0.6(c) 永不复用。
- 映射表（本卷第三节）登记：`0.6(c) conflict → 0.6 CH-C; 0.6(c) unreachable → 0.6 CH-D`。
- 所有交叉引用（方面 1–10 中"见 0.6(c)"）按映射表更新为新编号。
- 更新记录入版本变更日志（0.13）。

**【反例 22-A】情态动词模糊导致编译歧义**

错误处置：成文法某段写道"团队**建议**在金丝雀发布时使用自动化回滚判据"。编译规范无法判定此为硬约束（MUST）、软约束（SHOULD）还是可选（MAY）——"建议"不在四档内。编译器自行推断为 SHOULD，产出技能卡片带警告级检查。实际意图是 MUST（金丝雀无自动回滚 = 爆炸半径失控，属硬安全要求）。

违反条款：M31（非四档情态动词）；FM-12 同型（成文法表述不可编译）。

后果链：技能卡片的回滚判据检查为警告级 → Agent 在执行时因时间压力跳过警告 → 金丝雀放量无自动回滚 → 生产事故 → P0。检测点：M31 静态扫描（编译前即可捕获"建议"等非四档词）；若扫描遗漏，8.2.7 评审点一的备料检查应捕获（评审材料中的情态动词合规性）。

与正例分界：正例用"必须"表达硬义务，编译产物生成强制检查；反例用"建议"表达模糊意图，编译产物生成错误级别的检查。**分界不在意图好坏，在意图是否被无歧义地表达**——成文法的职责是把意图翻译成编译器可消费的信号，不是让编译器猜测意图。

## 0.23 编译接口

### 0.23.1 定位与权威关系

本条是**成文法向编译规范施加的全部约束的汇纂**（你的接口图正典化）。权威关系：

> **成文法 > 编译规范。** 编译规范不得修改成文法。若编译规范发现成文法有缺口（某段规则无法编译、某性质无法实现、某参考资料无法提取），走成文法的 R2 重审门槛（7.2.4），而非自行补写或忽略。

**接口方向**：单向约束（成文法 → 编译规范）。编译规范对成文法的反馈只能通过 R2 通道，不能通过修改成文法文本。

### 0.23.3 层次一/层次二接地编译的钩子

- **层次一（框架→技能卡片）**：10.2.3 认知编译层为本层次的成文法表述；编译规范实现 10.2.3 声明的编译忠实性判据。
- **层次二（设计产出→谓词+工件）**：**10.2.3bis 设计接地编译**为本层次的成文法表述（将在方面 10 重写批次交付）；核心纪律 = "叙事性设计活动合法，但只有落地为谓词/工件的产出获得决策权重"；编译规范实现 informal→formal 的转换规程与 FVR 接线。

两层次的编译规范可独立演进，但共享：(i) 产物 schema 的基础类型系统；(ii) 版本管理机制；(iii) 失败分类（FM 目录）。

### 0.23.4 编译规范发现缺口的 R2 通道

编译规范编制/运行过程中发现成文法缺口时：

1. **归类**：缺口属于甲类（成文法应补）还是丙类（编译规范可自行解决）？
2. **甲类缺口**：起草 R2 重审提议，附：(i) 缺口描述（哪段文本/哪个性质无法编译）；(ii) 影响分析（阻塞编译还是降低质量）；(iii) 建议修复方案（可选多个）。走 7.2.4 材料性门槛（编译不可行 = "触及硬性质"的材料性满足）。
3. **丙类缺口**：编译规范侧自行解决，记录于编译规范文档；若解决方案影响成文法语义（如引入新的隐含假设），升级为甲类。
4. **禁止**：编译规范不得静默忽略缺口、不得自行补写成文法语义、不得以"编译限制"为由降低成文法要求。

### 0.23.6 执行示范

**【正例 23-1】编译规范发现成文法缺口，走 R2 通道**

编译规范编制过程中发现：0.18 S4 包络校验步骤要求"聚合 cost_profile"，但 0.17.2 cost_profile 字段的聚合算法（多候选卡片如何合并为单一 ledger）未在成文法中定义——编译规范无法确定聚合是取最大值、加权平均还是逐项并列。

处置：归类为甲类缺口（规程级算法不完整，属成文法职责）。起草 R2 提议：(i) 缺口 = S4 cost_profile 聚合算法未定义；(ii) 影响 = 阻塞编译（S4 技能卡片无法生成）；(iii) 建议方案 = {方案A: 逐项并列（保留全部代价维度，最保守）；方案B: 按目标属性分组取最大值；方案C: 加权平均（需权重来源）}。提议附 0.18 S4 的步骤日志模板草案作为修复参考。

R2 评审通过方案A（最保守，与 0.6(b) 保守界原则一致）。0.18 S4 修订，增加聚合算法子条款；0.17.2 cost_profile 字段增加 `aggregation_semantics` 子字段。编译规范继续编制。

**【反例 23-A】编译规范自行补写成文法语义**

错误处置：同一缺口（S4 聚合算法未定义），编译规范编制者认为"加权平均最合理"，直接在编译规范中定义加权平均算法，未走 R2 通道。编译产物生成，技能卡片按加权平均聚合代价。

违反条款：M35（甲类缺口未走 R2）；0.23.1 权威关系（编译规范修改了成文法语义）；0.6(b) 保守界原则被绕过（加权平均可能低估极端代价）。

后果链：某选型决策中，候选 X 的 latency_budget_delta 极端值被平均稀释 → S4 判定 reachable_with_cost → 选中 X → 上线后极端场景触发延迟违约 → P0。根因：聚合算法是**成文法级的算法选择**，不是编译实现细节；编译规范的"合理"判断未经过成文法的治理流程（R2 评审会考虑保守界原则，编译规范编制者不会）。

与正例分界：正例把缺口**上交成文法治理**；反例把缺口**在编译层私自填补**。分界判据：缺口的修复是否改变成文法语义——改变了，就是甲类，必须走 R2；没改变（纯实现细节），才是丙类，编译规范可自行解决。
