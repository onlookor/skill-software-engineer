# 谓词化执行级计划（定义优先）

> 状态：计划，未进入实现。版本保持 0.9.0。
> 本文件不修改母本、不修改《编译规范》正文、不动卡片；凡涉及这两处正文的条目一律标「待批」，批准前不生效。
> 事实基线（2026-11-18 核查）：定义在母本 4533–4541；规程在《编译规范》528–566（T1–T5）；接线是 14 张卡的 S6；执行级为零。缺四样东西：叙事推理步没有记录载体；谓词增量没有同一性定义；谓词→方面映射不存在；`style` 之外没有投影规则或豁免机制。

## 0. 目标、非目标与“够”的定义

**目标**：让“叙事推理步 → 谓词增量 → 白板入板 → 版本向量推进”这条链可被记录、复核，并最终可被检查器判定。

**非目标（本轮及定义期）**：

- 不写检查器、不加校验规则、不改技能包；
- 不改母本与《编译规范》正文（相关条目全部「待批」）；
- 不动卡片，不补 S6，不改 `predicate_writes`；
- 不把“文档写完”当作定义完成。

**定义到什么程度算够**：四个定义各自有一组黄金样本与反例；两名独立标注者按定义标注，一致率达到第 3 节的门槛；给定样本的判法唯一；映射与投影能在试点上逐字复现。缺一项就不算完成，不用“已经讨论清楚”替代。

## 1. 四个定义

### D1 叙事推理步的记录载体

| 项 | 内容 |
|---|---|
| 定义对象 | 一条 `narrative_step` 记录：它回答什么设计问题、依据什么线索、得出什么结论、产出一个谓词增量或一个保全工件、在 S0–S6 的哪个位置发生。 |
| 落层 | 仓库内新 schema：`pilot/schemas/narrative-step.schema.yaml`（或同层等价文件）；规范性锚点补入《编译规范》T1（**待批**）。 |
| 是否需批准 | schema 属仓库约定，不需人类批准；《编译规范》T1 的正文改动**待批**；母本不需要改。 |
| 判据 | 每条记录必须齐备：稳定 `step_id`；`decision_point`；一个可回答的 `question`；非空 `trace`（依据与排除项）；`outcome_kind` 恰为 `increment` 或 `preservation` 之一；`position` 指明在哪个 S 步之前／之后／之间；执行者与时间。`step_id` 不得与 S0–S6 的步骤 id 冲突。 |
| 与 543 的关系 | S0–S6 仍是程序化步骤，**不翻译成谓词**；叙事步只发生在 S0–S6 之间或之外，产出的是**候选增量**；S6 是这些候选收敛为权威增量的位置。定义不得把叙事步塞进 S0–S6 的内部，也不得用叙事步替代任何程序化步骤。 |
| 失效反例 | ① 把某张卡的 S3 动作原样抄成一条 `narrative_step` 也能通过 → 边界过松，与 543 冲突；② 同一段文字，两名标注者一个判一条、一个判两条 → 边界不可判定；③ 一条记录既无增量也无保全工件仍通过 → `outcome_kind` 没有约束力；④ 叙事步的 `position` 被写成“替代 S4” → 违反 543。 |

### D2 谓词增量的同一性

| 项 | 内容 |
|---|---|
| 定义对象 | “新增了一个谓词”的同一关系：比较单位是规范化后的原子 `name(args...)`；比较基线是该决策点上一次白板快照。 |
| 落层 | 《编译规范》T1／T2 的判定细则（**待批**）；仓库内 schema 补充字段（`before_snapshot`／`after_snapshot` 或等价）。母本 4533–4541 已给“每个叙事步必须产生增量”，本定义只补“同一性”，不改母本。 |
| 是否需批准 | 《编译规范》正文**待批**；schema 不需批准。 |
| 判据 | ① 规范化：谓词名不改写，参数按声明顺序、字符串去引号歧义、容器按稳定序规范化；② `name` 相同且参数元组相同 → 不算增量（重复写入，记 `no_op`）；③ `name` 相同但参数元组不同 → 算一个增量；④ `name` 不同 → 算一个增量；⑤ 保全工件只在“该步不改变谓词集合、只补证据或维持既有性质”时替代增量，工件种类必须来自封闭清单，且必须写明它保全了哪条既有谓词或哪条不变式。 |
| 失效反例 | ① 同一原子重复写两次被计为两个增量 → 同一性过松；② 只改一个参数常量被计为 `no_op` → 同一性过粗；③ 把一份普通日志声明为“保全工件”就绕过增量 → 工件清单与“保全对象”字段形同虚设；④ 增量比较不取基线快照，只与当前白板终态比较 → 无法区分“新增”与“本来就有”。 |

### D3 谓词→方面的映射

| 项 | 内容 |
|---|---|
| 定义对象 | 每个谓词名对应的方面集合；一次谓词写入如何推进白板版本向量。 |
| 落层 | 仓库数据：`registry/predicate_vocabulary.yaml` 增加 `aspects` 字段，或新增 `registry/predicate_aspects.yaml`；计数规则写入《编译规范》（**待批**）。母本 0.7 的版本向量语义不改，只在编译规范侧补“一次写入如何计数”。 |
| 是否需批准 | 数据文件属仓库内，不需人类批准；计数规则涉及《编译规范》正文，**待批**。 |
| 判据 | ① 映射覆盖：卡片 `predicate_writes` 与试点白板里出现的全部谓词名，100% 有非空 `aspects` 或已登记豁免；② 多方面谓词：一次新增原子，按其 `aspects` 集合对**每个**方面各 +1（一次事件、多方面各记一次）；③ 同一原子重复写入不推进任何方面；④ 方面 4／5／7 允许暂时没有计数器，但**有谓词映射到该方面时必须补键**；映射并集必须等于白板版本向量的键集合，不允许“谓词落在没有键的方面却静默跳过”。 |
| 失效反例 | ① 多面谓词只加一个方面 → 漏计；② 一次写入给三个方面各加 2 → 重复计；③ 未映射谓词被当成“无方面”跳过且检查仍绿 → 映射缺口被吞掉；④ 方面 4／5／7 被固定写成 0，但存在映射到该方面的谓词 → 向量与模型不一致；⑤ 只改参数常量也推进向量 → `no_op` 判定失效。 |

### D4 `style` 之外谓词的投影规则或豁免

| 项 | 内容 |
|---|---|
| 定义对象 | 卡片 `outputs.predicate_writes` 中除 `style` 之外的谓词，哪些需要投影规则，哪些走封闭豁免。 |
| 落层 | 豁免清单：`registry/projection_registry.yaml` 增加 `predicate_exemptions`（谓词名、理由、责任人、到期触发条件、证据指针）；规范性规则写入《编译规范》5.7／第二章（**待批**）。 |
| 是否需批准 | 数据文件不需批准；《编译规范》正文**待批**。 |
| 选择 | **选“封闭豁免机制”为主，按需补投影规则**，不一次性写 33 条投影规则。理由：5.7 的 P1–P4 是“从作用域生成谓词元组”的投影，而卡片里绝大多数非 `style` 谓词是决策记录／证据／注册表引用（如 `step_log`、`exclusion_record`、`verdict_table`、`selection_context`），不是作用域生成物；为它们硬造投影规则会把“记录”误当“生成”。 |
| 判据 | ① 卡片 `predicate_writes` 去重后的每个谓词，要么有投影规则，要么有一条豁免记录；② 豁免必须带责任人、到期触发条件（例如“首次多写入方部署前”或“该谓词进入生成型 pact 时”）、理由与证据指针；③ `style` 继续走 5.7，且投影结果与试点白板逐字一致；④ 生成型 pact 里出现的谓词不得豁免，除非人类另行批准。 |
| 失效反例 | ① 写一条“全部非 style 谓词豁免”的兜底记录 → 封闭清单失效；② 豁免没有责任人或到期条件 → 永久漂移；③ 一个谓词在生成型 pact 里被使用却仍在豁免清单 → 豁免越界；④ `style` 投影与白板字符串不一致 → 5.7 未被真正接通。 |

**数量口径说明**：你给的背景是“另有 7 类谓词”。按 14 张卡的 `outputs.predicate_writes` 去重，实际出现 **33 个谓词名**（`G-TRUNK-CSL` 一张卡就有 8 个非 `style` 名）。本计划以 33 个为覆盖面；若只按 CSL 的 7 类做，会漏掉其他卡的 25 个名字。

### 2.1 设计文档的同步与冻结口径（已获批 2026-11-18）

设计文档 `plans/predicate-ization-design.md` **不等到 P0 四组证据全过才开工**。口径为：

1. **随 P0 同步成稿**：设计文档与 P0 的定义工作同一批推进，承载 D1–D4 以及谓词类型／三值语义／编译债务的定义；本计划只保留顺序、出口与验收，不复制定义。
2. **每标一批黄金样本回改一次定义**：第 3 节第 1 项每完成一批标注，就回改设计文档中的相应定义；不攒到最后统一改。
3. **P0 通过时冻结**：P0 出口达成（第 3 节四组证据全过）时，设计文档冻结为 v1.0，状态从 draft 改为 frozen。
4. **冻结之后才允许写 AST 与求值器实现**：设计文档冻结前不开工解析器／AST／求值器／检查器；冻结后实现以设计文档为规范目标。
5. **P0 未通过**：设计文档保持 draft，不冻结、不开工；不得用“先写实现再倒推定义”绕过。

这条口径替代此前“P0 四组证据全过再开写设计文档”的说法。原说法存在循环依赖：定义要靠黄金样本检验，而样本的标注又依赖定义成形；先冻结证据再写定义，会把无法验证的定义写成规范。

## 3. “定义完成”的可核对验收形式

承诺以下四组证据，缺一组即判定义未完成：

1. **黄金样本集**：`pilot/predicate-ization/golden/` 下至少 20 条叙事步样本（10 条合规、10 条违规），每条带 `expected_verdict` 与理由；另有 10 条增量同一性样本（5 条 `new`、5 条 `no_op`）、33 条谓词映射样本、18 条卡片 S6／豁免样本。
2. **双人独立标注**：两名标注者在不交流的情况下按定义标注同一批 20 条叙事步；对“是否一条步”“是否有增量”分别计算一致率。门槛：一致率 ≥ 90%，Cohen's κ ≥ 0.80。分歧超过 2 条 → 修改定义后重标，**不得**用“讨论后同意”把分歧算成一致；≤ 2 条分歧必须逐条登记为“已知边界”。
3. **判法唯一性／变异测试**：对 10 条负例各做一处单字段变异（删 `trace`、改 `outcome_kind`、把增量换成普通日志、把同一原子重复写、给多方面谓词只加一个方面等），要求 10/10 从“通过”翻成“违规”，且翻因与变异字段一一对应；同一输入两次运行判法一致。
4. **试点复现**：D3 的映射重放必须逐项复现 `whiteboard-pact-dsh.yaml` 的版本向量；D4 的 `style` 投影必须逐字复现白板里的 `style(pact-dsh, ...)` 项。任何一项对不上，定义期不算完成。

**“够”的判定**：四组证据全过，且黄金样本里没有一条需要“定义之外的判断”才能标注；若出现一条，必须把它写进定义或登记为已知边界，否则不得宣布定义完成。两名标注者不可得时，可用两次独立 agent 标注＋人工裁决替代，但人工裁决本身也计入证据，不得只留“已人工确认”。

## 4. 与技术债的衔接

| 技术债 | 依赖谓词化的哪项定义 | 何时回头清 | 缺了它退化成什么 |
|---|---|---|---|
| **观测是否覆盖所述缺陷**（`validators/README.md` 已知边界；`V09-checklist.md`；`TECH-DEBT.md` 将来改版方向“观测输入与期望值的语义独立性”） | D1（叙事步记录缺陷陈述与观测问题）＋ D2（增量同一性把观测对象锚到谓词） | P1 之后可做结构化核对；P2 之后可做可执行核对 | 没有 D1 的稳定 `step_id`，V09 只能读叙述；“缺陷在奇数分支、只观测偶数输入”仍只能靠人看出来 |
| **期望值来源**（`TECH-DEBT.md` 将来改版方向；`validators/README.md` 已知边界“期望值独立写在 repro.md，但不证明期望值是对的”） | D2（同一谓词换参数算不算新事实）＋ D4（非 `style` 谓词是否有投影／豁免） | P2 之后 | 没有 D2，期望值仍是手写字面量，无法区分“同一谓词不同参数”；没有 D4，非 `style` 谓词没有投影依据，期望值只能人工判定 |
| **V09 里可判的部分**（`V09-checklist.md` 的根因／覆盖项） | D1（步骤与问题可追溯）＋ D3（谓词是否真正入板、向量是否推进） | P2 之后 | 没有 D3，V09 无法判断“写了谓词但向量没动”或“向量动了但没有对应谓词”，仍全人工 |

**不在谓词化清理范围内**：`TECH-DEBT.md` 第 6 条（同进程伪造没有机械出口）与 8.4（导入期行为篡改）不靠谓词化解决，仍需沙箱／动态追踪。谓词化只补语义锚点，不补进程完整性。

**一个必须先说清的依赖**：谓词化是仓库自身编译流水线（阶段 C／M2）的语义层，不是技能包可直接调用的检查器。要让上表三条技术债真正在技能层变可判，还需要一步“把 `repro.md` 的缺陷陈述映射为 `narrative_step` ＋ 谓词增量”的适配；该适配不在本计划范围内。没有这一步，谓词化对分发给用户的技能包**直接效果为零**。
