## 一、完成判据：规范里有没有定义

### 1.1 规范原文

**（a）产物侧——编译规范 5.1 C7「产物发布与版本对齐」**

> 操作：`compilation_artifact(version, framework_version, registry_version, cards)` 装配（M34：版本一致 + 已做忠实性检查）；SM-CA `compiling → valid` 迁移；覆盖率报告（含锚定缺口清单、软性质未覆盖清单、存疑来源清单）随产物发布。
> 判定谓词：`version_consistent ∧ fidelity_verdict = pass`。
> 失败分支：版本失配（编译期间注册表变更）→ 产物 `invalid`，重启编译。

**（b）部署侧——母本 10.2.5「接地编译的验收判据」**

> 框架在一个部署中"已接地"的判定（全部为机器可查或评审可查）：
> 1. 白板存在且谓词模式与本文档一致（模式版本号匹配）；
> 2. 方法注册表、批准注册表、守护规则注册表、FVR、投影规则五个注册表非空且版本在案；
> 3. 技能卡片（或人类检查单）编译产物版本与注册表版本一致（E4）；
> 4. 全部硬性质 FVR 接线完成且首轮全量执行有证据工件；
> 5. 评审点集合（8.2.7 裁剪后）已排期且有责任人；
> 6. 部署可行性勘察结论（批准角色存在性、P0 响应能力、CI 能力）已登记。

**（c）状态机定义——母本 0.21.3**

> SM-CA `valid`＝编译成功，忠实性检查通过，与注册表版本一致。
> SM-GS `grounded`＝六判据全过，正常产出。
> 〔R7-11 注：`grounded` 的语义为**声明完整＋转换期限在案**，不是**能力完整**。〕

**（d）分层边界——编译规范 13.1**

> 层一：编译器实现验证（C0–C7、F1–F3）——测试对象 = 编译器；
> 层二：编译产物接地验证——验证编译产物在真实项目中通过 10.2.5 六判据；属 todo.md 3.5（试点），不在本章。

**（e）目标声明——编译规范 1.5**

> 本规范的设计目标 = 使编译产物通过接地验收。

### 1.2 裁决：规范**没有**「接地编译完成」这一单一术语的定义

规范给出的是两个可判定端点，没有把二者合并成一个「完成」条款：

| 端点 | 判据 | 当前状态 |
|---|---|---|
| SM-CA `valid`（产物可用） | `version_consistent ∧ fidelity_verdict = pass` | 已满足：`version_consistent=true`、F1/F2/F3 全 pass、`predicate_satisfied=true` |
| SM-GS `grounded`（部署已接地） | 10.2.5 六判据全过 | 已满足：6/6 |

凡出现 6/6 必须附分布：**pass 39 / fail 0 / escalate 0 / vacuous 9；fail 项：无**。
vacuous 9 = M14、M20、M25、W7、X6、R8、E1、E2、M8（空真：域无实例或显式空集；X6 为 `shared_data_access` 显式空集）。其余 30 条为机械校验。

## 三、关键路径与依赖顺序

### 3.1 最小可行链（口径 A）

```
H1 人类选定口径（A/B/C）+ 回答「发布是否算终点」（§6）

      ├─ 若 A：

      │    S4 若人类把发布纳入完成：执行 .12 发布动作          ← 需人类指令

      │

      │    S6 其余 kind 的端到端用例登记 + 13.3 反例库执行记录

      │
      └─ 若 C：在 A 之上执行 S4（发布），并按发布后重跑 E4/装配校验
```

### 3.2 依赖关系

- **必须先做**：H1（口径不定，后续动作无法归一）。
- **可并行**：G5 的消费形态调研、G6/G9/G10 的口径确认，三者互不依赖；S1 已无等待。
- **别人的输入**（非 agent 可自主取得）：

  - 目标仓的 source registry 实体（SRC 的上游，本切片只有试点数据）。
- **顺序硬约束**：S1 → S2 → S3（报告依赖锚索引读数；复跑依赖报告改动）。S5 → S6 → S7（精化依赖上游数据；套件依赖精化后的卡）。

## 四、重新审视：CFG／CRD／DPS／SRC 维持 0.1.0 骨架，是否成立

### 4.1 既有理由

`run-log.md §30` 与 §33 记录：四者「价值链在本切片未打通」（CFG←SCH 部署/调度；CRD←CFG；DPS←方面 8/9；SRC←目标仓 source registry 实体），「先行精化会把未消费的上游谓词写成硬依赖，制造假 DAG」，故维持 0.1.0 骨架、登记后续批次。

### 4.2 在「完成编译」目标下，这个理由**不成立**——但不是因为要精化

「等上游打通」把「不精化」的正当性建立在「上游未打通」上。若完成判据不检查这四张卡是否有步骤，那么**它们是否精化与完成无关**，该理由既不构成阻塞、也不构成免责；它只是一个与目标无关的排期说明。反过来，若完成判据检查它们（口径 B），「等上游」也不是可接受的完成路径——它意味着完成被外部输入无限期挂起。

### 4.3 明确回答一：口径 A 下，**允许**四张仍是骨架卡

依据（逐条）：

1. **10.2.5 判据三**只要求「编译产物版本与注册表版本一致（E4）」——四卡 `artifact_version` 均已对齐 `.12`，E4 18/18 `match=true`。
2. **10.2.5 判据四**只要求「全部硬性质 FVR 接线完成且首轮全量执行有证据」——FVR 覆盖 39 条硬性质，分布 pass 39 / fail 0 / escalate 0 / vacuous 9（fail 项：无）。判据四不按「每 kind 卡是否有实质步骤」计量。
3. **编译规范 5.1 C4** 的判据是「每条硬性质至少被一张卡片认领」——当前 39/39 被认领；C4 不要求每个 kind 都有实质卡。
4. **编译规范 5.1 C7** 判定谓词只有 `version_consistent ∧ fidelity_verdict = pass`——不含「kind 精化度」。
5. **编译规范 13.1** 明确把 kind 覆盖矩阵（13.2）划归层一编译器验证，层二接地验证只看 10.2.5。

### 4.4 明确回答二：口径 B 下，**不允许**；打通路径与缺环

- **不允许**，因为 13.2 要求「kind 覆盖矩阵每格至少一条正例 + 一条边界例」，且正例链路必须包含「卡片消费（某步骤 `registry_refs` 引用该 kind 条目）→ F2 引用闭合通过」；0 步卡不存在消费步骤，这一格直接为空。
- **打通路径**：四卡各补 0.18.2 通用 S0–S6 七步（动作逐字取母本，与 DFL/STP/CSL/OWN/SCH/RLP 的 0.2.0 口径一致）+ 每卡在步骤里加一条 `registry_refs` 消费（正向）+ 一条条目缺失的失败分支（边界）。
- **缺哪一环**：
  - CFG：缺 SCH 的部署/调度决策产物（`deploy_strategy` 现只有 DEP-PACT-DSH-01 一条，不含调度决策）；
  - CRD：缺 CFG 的协调决策产物；
  - DPS：缺方面 8/9 的质量与可观测产出（切片内无生产监测数据）；
  - SRC：缺目标仓的 source registry 实体（切片内仅试点数据）。
  - 另：四者均无自有或已登记的 0.18.4 变体；变体登记须人类走 0.18.8／R2。

### 4.5 禁止的两种写法

- 不得把这四张写成「已精化」「已覆盖」——它们是 0 步骨架，事实如此。
- 不得因为「口径 A 允许」而把它们从缺口清单里划掉——在口径 B 下它们是缺口，是否走 B 是人类的选择，不是文档可以抹掉的事实。

## 五、C7 的 16 条软性质：是否构成完成判据

### 5.1 规范口径（两处，一致）

- 编译规范 3.3 映射表：软性质「覆盖为可选，未覆盖登记为覆盖率缺口（非阻塞）」。
- 编译规范 3.4：性质锚点中软性质未覆盖 → 「计入分母同时登记『软性质未覆盖清单』（**不阻塞发布**，入 G9 度量）」。
- 编译规范 5.1 C7：判定谓词不含软性质；三清单随产物发布，非发布门槛。

### 5.2 结论

**不构成完成判据。** 口径 A/B/C 下均不阻塞完成。

### 5.3 「非阻塞」不等于「可永久忽略」——对终点的实际影响

1. **运行期没有执行者**：16 条软性质目前 0 条被 FVR 或检查器以 `property_id` 绑定；偏离只能靠人工评审与 G9 趋势发现，不会有机械信号。
2. **覆盖率读数永远到不了 1.0**：3.4 把它们计入分母，因此「锚定覆盖率」这一度量在完成时仍 < 1；这不是缺陷读数，但会被误读为「未完成」。
3. **完成声明的边界**：完成后只能说「39 条硬性质有执行者、16 条软性质已登记为覆盖缺口」，**不能**说「全部性质有执行者」。
4. **持续义务**：16 条是 G9 的常驻度量项，属评审输入（8.2.7）；若长期无变化，应按 0.13 作为框架质量信号处理，而不是当作已结项。
5. **若要纳入完成判据**：需为 16 条各写检查器 + 判定口径，属新增工作量与新增裁决（等同口径 B 的扩展），必须人类单独立项。
