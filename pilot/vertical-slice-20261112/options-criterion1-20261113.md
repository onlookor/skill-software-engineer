# 判据一方案：白板 `pattern_version` 缺定义（D-10）

> 状态：**方案，未执行**。母本未动。三条主路线＋一条被判非法的第四路线。
> 事实：10.2.5 判据一原文＝「白板存在且谓词模式与本文档一致（模式版本号匹配）」；全文再无「白板模式版本号」的定义。0.7 只定义白板**内容版本**（写入单位、乐观并发、`version_vector`），未定义**模式版本**。当前 `whiteboard-pact-dsh.yaml: pattern_version: null`。
> 影响：判据一现为 fail；另两条 fail 为判据四。10.2.5 当前 4/6。

## 路线 A：改母本，定义「模式版本号」

**改哪层**：母本（0.7 或 10.2.5 自身）。推断最小改法：在 0.7 的版本语义段末追加一句，定义「白板模式版本＝0.21.6 机器层谓词块的模式标识；其值由谓词块的规范化指纹给出，谓词块任何语义变更即递增」。也可只在 10.2.5 判据一后加解释句。

**具体改什么**：
- 0.7 段尾追加一句（同段追加、不增行，冻结裸锚错位 0，与第 3 批同法）；
- 或 10.2.5 判据一括号内追加定义（同段追加）。

**对现有结论的后果**：
- 判据一从「不可判定」变为可判定；白板填入按定义算出的值后，判据一可 pass → 10.2.5 上限升到 5/6（若判据四仍 fail）。
- 若定义取「谓词块指纹」，则母本 0.21.6 每次改动都会改判据一的值——需要同步机制，否则判据一会随母本编辑抖动。
- 不改变 S4/S6 verdict，不改变 E4。

**代价**：
- 母本改动属高影响（跨 10.2.5 与 0.7 两个位置），需人类批准＋changlog 登记＋锚点重冻（同段追加则 0 错位）；
- framework_version 哈希变更 → artifact／卡片／ADR 三处传播，产物序号 +1；
- 需补一条「指纹算法」的可执行定义，否则仍是新歧义。

**风险与边界**：放松的是「母本零改动」，收紧的是判据一的可判定性；若只在 10.2.5 加解释而不在 0.7 定义模式，两处语义可能分叉。

**推荐度**：最彻底，但成本最高、周期最长；适合作为「最终形态」，不适合当前冲刺。

## 路线 B：部署级临时口径（不动母本）

**改哪层**：部署级数据＋AD账（记「口径 ADR」，非母本）。

**具体改什么**：
1. 定义 `pattern_version := "pv-" + sha256(规范化后的 0.21.6 机器层谓词块)[:12]`；
2. 在白板写入该值，并在部署记录里写明「本值是按部署口径计算的、母本未定义的字段」；
3. 记一条**保守假设/口径 ADR**（可推翻指标＝母本一旦定义模式版本号，即改用母本定义并重算）。

**对现有结论的后果**：
- 判据一可判为 pass，但属「按部署口径 pass」，不是「母本定义后 pass」；10.2.5 从 4/6 → 5/6，须在记录里显著标注口径来源。
- 不改母本、不改 framework_version、不触发锚点重冻；artifact 序号 +1（白板/产物内容变更）。
- 不改 S4/S6/E4。

**代价**：低。一次白板编辑＋一条 ADR＋一次 10.2.5 重跑。

**风险与边界**：把「不可判定」变成「按约定可判定」，有**假接地**风险——判据说「与本文档一致」，而本文档没有该定义；若将来母本定义与部署口径不同，判据一需回退重判。必须显式写「这不是母本语义」。

**推荐度**：当前性价比最高；须人类明确接受「口径 pass」的读法。

## 路线 C：维持 null，接受 fail

**改哪层**：不改。
**具体改什么**：仅把 D-10 的处置结论从「待定」改为「接受 fail」，并在 10.2.5 记录里写明「判据一因母本缺定义而不可判定，按 fail 记，不美化」。

**对现有结论的后果**：10.2.5 维持 4/6；ADR-DP1-STYLE 保持 provisional。无版本传播、无锚点改动、无 ADR 新增（仅登记既有 D-10）。

**代价**：零。
**风险与边界**：接地永远差一条；但这正是 10.2.5 设计意图——未定义就不算接地。不会制造假接地。

**推荐度**：最诚实；若短期不打算动母本，这是默认路线。

## 路线 D（判为非法，仅供对照）：在《编译规范》定义

**为什么不合法**：成文法 > 编译规范（文档定位声明）。「模式版本号」是 10.2.5 的成文法用语，编译规范只能实现映射，不能替成文法定义其含义；否则违反 0.23.4 的 R2 边界。**不建议，也不计入三选一。**
