## 1. 问题

`ADR-README-01` §6 采纳方案甲：seed 资格口径正式变更后，对全部 `seed` 条目按新口径全量重判，**不通过者回落 `draft`**。但母本 0.17.5 L451 的迁移权限表只有：

- `draft→active`（高影响）；
- `active→deprecated`（高影响）；
- `draft→seed`（bootstrap 专用，低影响）；
- `seed→active`（重验证 diff 为空时，低影响）。

**没有 `seed→draft`。** 方案甲的执行链在最后一步没有合法出口：重判失败的条目仍声明 `seed` 会违反 C-ST，而任何回落动作都只能靠人类逐条临时特批。

## 3. 决策建议

### 3.1 是否必须补：必须

1. **合法性闭环**：方案甲的「不通过者回 draft」没有母本出口；不补，方案甲只能在每次失败时开特批，规则退化为个案裁量。
2. **文本已依赖**：§2.1 三处已经假设该迁移存在；不补则母本与台账/README/代码持续分叉。
3. **可审计性**：特批没有统一记录形态，无法区分「合法的资格撤回」与「手工篡改状态」；补一条权限后，迁移可用 `transition_id`／`condition`／`evidence` 的同一形态留痕。

### 3.2 权限级别建议：**高影响（批准注册表类目），不与 `draft→seed` 同级**

判断依据（四条）：

1. **方向不对称**。`draft→seed` 是「尚未被消费的条目进入可消费集合」，母本把它的低影响理由写得很清楚：「seed 状态本身即风险标记，重验证义务见 0.17.6(3)」。`seed→draft` 是**撤回**：条目从 S1 可消费集合中移出，已生成的决策 ADR 依据随之失效。
2. **与唯一的撤回型迁移同构**。母本对 `active→deprecated` 定高影响，并要求「弃用 ADR：附迁移条款 + 批准」（L444）、「存量决策不失效（迁移条款保护：存量使用登记 + 迁移路径 + 最后负责时刻）」（L449）。`seed→draft` 同样是撤回，只是存量面更窄（消费方已有「依据种子条目，待重验证」附注，L448），故可**减轻执行强度**，但不改变「撤回型 = 高影响」的定性。
3. **证据链断裂**。seed 条目被 S1 消费后，决策 ADR 的依据指向该条目；条目退回 draft 后，该 ADR 的依据不再处于任何可消费状态。0.17.5 L448 的自动附注只提示、不阻断，也不自动修复。
4. **反向不成立**。若定为低影响（只需简记），重判批次可静默批量撤回已被消费的条目，且无需人类确认；这与方案甲「须人类逐条裁定」的要求冲突。

**执行强度（高影响内的轻量形态）**：不为每条回退单开 ADR。由触发口径变更的那份 ADR（方案甲 §6.2）承担**类目级批准**，逐条回退在同一 ADR 下以 `seed_rejudication` 记录＋人类逐条裁定留痕。这样既满足「批准注册表类目」，又不制造逐条 ADR 的数量爆炸。

> 备选判断：若人类认为「seed 已被标记为待重验证」足以吸收撤回风险，可降为低影响（简记）。代价是接受批量静默撤回。本 ADR **不推荐**该选项，理由见上第 4 条。

### 3.3 审批主体

- **类目批准**：人类责任方（用户本人）。批准对象是「`seed→draft` 迁移权限」这一注册表类目，形态为母本修订（0.13 完整 ADR ＋ changelog）。
- **逐条执行**：仍由人类逐条裁定（与方案甲 §6.3 一致）；Agent 只计算差异、登记字段，**不得自行改写 `status`**。
- **禁止**：以「修正条目」「挂 Waiver」「沉默保留 seed」替代回退；三者都不改变「该条目在新口径下不合格」的事实。

### 3.4 触发条件（仅限以下情形）

1. 按方案甲 §6.2 认定的**seed 资格口径正式变更**已生效；
2. 全量重判显示该条目在新口径下 `SEED_CHECKS` 失败；
3. 人类已对该条目作出「口径差异／条目缺陷」裁定，且裁定结论是「不能维持 seed」。

不得用于：规避单条检查、绕开准入、在口径未变更时清理历史条目。违反者按 0.13 追责留痕。

### 3.5 与「通道终止后此迁移关闭」的关系

- 0.17.5 L451 末句关闭的是 **`draft→seed`**，不是本权限。
- 0.17.6(4) 规定通道终止后 `seed` **从生命周期移除**；因此 `seed→draft` 在终止后**无对象可迁**，自然失效（不是被单独关闭，而是前提消失）。
- **反回环约束**：`seed→draft` 不得重开 `draft→seed`。通道终止后，任何重新入库只能走 0.17.7（人工 `draft→active`）或编译通道；bootstrap 期内，回退后重新升 seed 必须是一次**新的** `draft→seed` 迁移，且以新口径全过为前提、单独登记，不得沿用原批次记录。
- **同批次防绕行**：同一重判批次中，不得「回退后立即重升」以规避失败项；重升前须证明失败检查项已修复，或人类明确裁定为口径差异。

### 3.6 前置与伴随义务

| 义务 | 内容 |
|---|---|
| 存量消费查询 | 迁移前查该条目是否已被决策 ADR／编译产物引用；有则登记受影响决策 |
| 迁移处置 | 对已消费的条目，参照 `active→deprecated` 的最小集：登记存量使用、给出处置（重验证／替换／保留并标注） |
| 台账记录 | 一条 `transition_id`（`from: seed`、`to: draft`、`scope`、`date`、`condition`、`evidence`、`impact_level: 高`、`provenance`）＋一条 `seed_rejudication` 差异记录 |
| 投影 | 重跑 `project.py` 重生成人类层；`自检报告.md` 与 `seed重判清单.md` 同源更新 |

## 4. 不补的后果

1. **每次重判失败都要临时开特批**：无统一条件、无统一记录、无统一影响级别，批次之间不可比。
2. **母本与三处实现持续分叉**（§2.1）：台账 `evidence`、README C-ST、工具文案都在描述一个不存在的权限。
3. **审计缺口**：状态变更无法从 `status_transitions` 机器追溯；「合法撤回」与「手工改 YAML」在记录上不可区分。
4. **行为扭曲**：操作者更可能选择「保留 seed ＋ 挂 Waiver」或「就地改条目以通过新口径」，而不是诚实回退——这两种做法都掩盖了口径变更的真实影响面。
5. **方案甲失去闭环**：重判清单产出后没有标准处置路径，§6.3 的「不通过者处置」只能停留在纸面。

### 6.1 `check_ledgers` 改法（已完成）

**为什么必须改**：旧逻辑要求「每条简记 `scope` 与当前全部 `status=to` 条目集双向相等」。`ST-STY-01`（`to: seed`，scope 覆盖 138 条）一旦回退 1 条，`declared - actual` 非空 → **硬失败**。合法撤回会先把台账判红，权限等于不可用。

**改法（时间切片＋迁入覆盖）**：

1. **后序迁出豁免**：以 `status_transitions` 列表序为时序（该节只追加）；取本条之后、`from == 本条.to` 且 `to != 本条.to` 的简记 scope 并集 `moved_on`，校验集合取 `effective = declared - moved_on`。
2. **正向校验保持原强度**：`effective - actual(to)` 必须为空——声明了迁移但条目没动，仍硬失败。
3. **反向校验改为迁入覆盖**：`actual(to) - inbound(to)`（`to != draft`）必须为空；`inbound` 为所有 `to` 相同的简记 scope 并集。未登记的非初态仍硬失败，同时允许同一状态的多条部分 scope 简记。
4. **初态特例**：`to == draft` 只校验 `(actual & touched) - inbound(draft)`；`touched` 为全部简记 scope 并集。从未登记过任何迁移的新 draft 条目不计入；曾登记过的条目静默退回仍硬失败。

**为什么不放松检查强度**：

- 豁免只覆盖「有后序**已登记**迁出简记」的条目；未登记的改状态仍被正向校验抓住。
- 「反向简记已写、状态却没改」仍硬失败（第 2 条）。
- `to=draft` 的初态例外只排除「从未出现在任何简记 scope」的条目（它们本来就出生为 draft），不排除任何曾登记条目的静默退回（第 3、4 条）。
- 净效果是**更强**：新增「非初态条目必须有迁入简记覆盖」与「曾登记条目静默退回」两类校验，同时消除合法回退的假阳性。

**改动前后行为（合成夹具实测，基线为现库 138 条）**：

| 场景 | 旧逻辑 | 新逻辑 |
|---|---|---|
| 基线：138 seed、无回退 | 0 硬失败 | **0 硬失败**（18 条 LEDGER ok，记录数不变） |
| 回退 1 条＋登记 `seed→draft` | **18 硬失败**（所有 `to: seed` 简记报 `declared - actual`） | **0 硬失败**（`effective` 137 ＝ 实际 seed 137） |
| 回退 1 条但**未登记** | 18 硬失败 | **18 硬失败**（仍抓住，非放宽） |
| 登记了回退但**状态未改** | 失败 | **1 硬失败**（`effective - actual`） |
| 回退后再升 seed（两条简记） | 失败 | **0 硬失败**（`moved_on` 在两次切片中分别抵消） |

**现有数据复核**：138/138、硬失败 0、软警告 0、自检记录 1,213、逐条翻转 0；母本 4,447 行／围栏 216 不变。
