> **状态：approved（2026-11-07 人类批准；schema 侧已落盘：母本 `@m:335`／`@m:462`＋`project.py`；数据侧见 §5.1，待下一批执行）**
>
> 关联：`G-STY-5`、`G-GOV-2`、`SO-3`、`SO-24`、`STY-021`、`STY-024`、`D-STY-5`、0.12、0.13、0.17.2、0.17.6、0.22。

## 1. 决策问题

`G-STY-5` 的 route 原文是：「人工裁决（书目 2 的登记面是否涵盖 1.2.4 全表）→ R2 提议澄清；澄清前保持留空」。

本 ADR 要裁决的正是这一问：**书目 2（以及 1／12／13／23 的组合）是否构成 1.2.4 表中 `STY-021`（约束排除法）与 `STY-024`（模式匹配）两行的行级出处。**

若不能，则给出第二条合法路径：把这两行认定为**框架内生元方法**（`source_class: mother-definition`）：出处记母本自身的 `row_id`＋`clause_id`，不追溯外部书目，从而在「无外部文献佐证」与「留空即缺出处」之间给出第三种可审计状态。

## 3. 判定标准：FIM-1（可复用判据）

一个注册表条目可以声明 `provenance.source_class = mother-definition`，当且仅当**同时**满足以下五项。缺一项即不成立，不得以「同表其他行也这样」类推。

| 编号 | 条件 | 可操作判据 |
|---|---|---|
| **F1** | **母本自建定义行** | 母本中存在一个表格行或条款，其中**名称与定义同处一行／一段**，且定义给出**过程或判定规则**（可回答「按什么步骤做／按什么规则判」），不是仅出现名称、仅举例、仅作反模式标签。 |
| **F2** | **行锚可反查** | 能给出 `row_id = "{条款号}-{母本行名}"` 与 `clause_id`，且 `resolve_pointer` 两者均可命中；`@m:` 行锚逐字落在该定义行。行名必须与母本表格首列逐字一致。 |
| **F3** | **无外部外包** | 该行／该条款没有「见书目 X」「由 X 定义」「参照 X」类外包语；且**没有任何书目把该行登记为自己的提取面**。若存在这样的书目，应走 `references`（外部出处），不得走 FIM。 |
| **F4** | **字段自足** | 条目的 `applicability`／`envelope`／`cost_profile`／`compatibility`／`constraints`／`anti_patterns` 等全部字段均可由**同节母本条文**推导；不存在「只有外部文献才能补足」的字段。若部分字段需外部补足 → 只能部分成立，须另案或拆条。 |
| **F5** | **可复现** | 第二名评审仅凭母本即可复算 F1–F4 并得到一致结论；ADR 必须逐字记录所用定义句与行锚。不可复现的「常识性解释」不算定义。 |

**FIM 的语义边界**：`source_class = mother-definition` 不是「无出处」，而是「**出处就是成文法自身的定义行**」。它登记的是 `row_id`＋`clause_id`，不是 `bib_id`；`references` 可以为空，但必须带一条「FIM-1 已满足」的说明，不能以空白暗示「无外部文献」＝「无出处」。`origin` 仍按产出通道独立登记（如 `hybrid`），不因 `source_class` 而改写。

**FIM 不适用的情形（否定清单）**：

1. 母本只提到名称、无过程定义（F1 失败）；
2. 母本有定义，但定义句本身以外部概念为上位（如「X 的泛化」）且该上位概念已被书目登记（F3 失败）；
3. 任一必需字段只能靠外部参数、阈值或基准补足（F4 失败）；
4. 该行已有书目登记面——此时 FIM 会变成规避 5.7 扩充的捷径，禁止使用；
5. 无法给出逐字行锚或行名与母本不一致（F2 失败）。

## 4. 对 STY-021／STY-024 的适用

| 条件 | STY-021（约束排除法） | STY-024（模式匹配） |
|---|---|---|
| F1 | `@m:1394`「从全部候选出发，用硬约束（合规、现状平台、团队能力）逐一过滤，剩余即可行集」——过程定义完整 | `@m:1397`「问题特征向量 × 各风格条目的适用条件谓词，求匹配度排序」——过程定义完整 |
| F2 | `row_id: "1.2.4-约束排除法"`；`clause_id: "1.2.4"`；`@m:1394` | `row_id: "1.2.4-模式匹配"`；`clause_id: "1.2.4"`；`@m:1397` |
| F3 | 书目 1／2／12／13／23 均未把该行登记为提取面（§2.2） | 同上；书目 12／13 分别覆盖另两行，反证逐行登记 |
| F4 | `applicability` 由「硬约束多而目标弹性大；棕地项目」＋过程定义推导；其余字段由同节条文可推 | `applicability` 由「作为以上各方法的子步骤统一执行；对 Agent 是强制步骤（纪律一）」＋过程定义推导 |

**结论：两行均满足 FIM-1，可登记 `source_class: mother-definition`（`origin` 维持 `hybrid`，见 §5.1）。**

### 5.5 规范细则（本 ADR 的权威正文）

> README 只保留指向本条的一句指引，不复制以下规则。

**(1) 两个正交的登记轴**

| 轴 | 字段 | 必填 | 值域 | 记录什么 |
|---|---|---|---|---|
| 产出通道 | `origin` | 是 | `manual`／`compiled`／`hybrid` | 值经不经编译器、骨架来自哪里 |
| 出处类别 | `source_class` | 否（未填＝未分类） | `external`／`mother-row`／`mother-clause`／`mother-definition`／`fallback` | 出处的实体类别 |

两轴可自由组合（如 `hybrid × mother-definition`、`manual × mother-clause`、`hybrid × external`）。**不得用 `origin` 表达出处类别，也不得用 `source_class` 表达产出通道。**

**(2) `source_class` 各值含义**

| 值 | 含义 | 必备指针 |
|---|---|---|
| `external` | 行级外部书目，且该书目的登记面覆盖本行（0.12 行级口径） | `bib_id` |
| `mother-row` | 出处是母本表格行本身（骨架／规格行，非定义行） | `row_id` |
| `mother-clause` | 出处是母本条款正文（非表格行） | `clause_id` |
| `mother-definition` | 出处是母本自建定义行，须过 FIM-1 F1–F5 | `row_id`＋`clause_id` |
| `fallback` | 整条记录的来源确为无表格无文献的人工判断 | 母本中描述该对象的行锚＋`manual_judgments` 条目 |

**(3) `manual` 的两类现状如何区分**

- `origin: manual` 只说明「人工录入、未经编译器」，**不说明有无出处**。
- 有出处的人工录入 → `source_class: external`／`mother-row`／`mother-clause`，`source_pointers` 带对应实体（如 `status_transitions` 的 `clause_id`）。
- 无表格无文献 → `source_class: fallback`，且必须在 `manual_judgments` 逐条登记判断理由（MJ-n）；禁止留默认值、禁止以空白冒充。
- **字段级与记录级分开**：一个条目的部分字段有出处、部分属人工判断时，`origin` 照通道登记、`source_class` 记**整条**的主出处类别，字段级判断由 `manual_judgments` 承接；不得用 `source_class` 概括字段级状态。

**(4) 与 `framework-internal` 旧称的映射**

方案 A 的 `origin: framework-internal` **不再使用**。凡历史文档出现 `framework-internal`，一律读作 `source_class: mother-definition`；`origin` 维持其通道值（STY-021／024 为 `hybrid`）。此映射只用于读旧文档，不得写入新数据。

**(5) 判定程序（谁判、判据、判错后果）**

| 环节 | 规则 |
|---|---|
| 谁判 | 登记者提议；人类责任方按 0.13 批准。ADR 须逐字记录所用定义句与行锚。 |
| 判据 | `mother-definition` 须 FIM-1 F1–F5 全满足；其余四值按 §5.5(2) 的实体类别判定。 |
| 机器边界 | `project.py` 只校验「值是否在域内」与「未分类计数」；**不推断、不默认填充、不做语义判定**。 |
| 判错：误标 `mother-definition` | 若该书目已登记该行（F3 失败）→ 撤销并改走 `references`。 |
| 判错：误标 `external` | 若无行级登记面（表级／节级下探）→ 按 0.12 表级不下探纪律驳回。 |
| 判错：误标 `fallback` 规避勘察 | 视为「未勘察」而非「无出处」，由 M15 生成勘察义务。 |
| 未填 | 记「未分类」；不得读作 `external`、`fallback` 或任何其他值。 |

**(6) 未分类的观测**

未填 `source_class` 不阻断；`project.py` 在 `自检报告.md` 汇总行报「未分类 n／总数」。该数值是观测项，不是合规判据。

### 5.6 A→A′ 转向记录

**原裁 A（扩 `origin` 枚举至 `framework-internal`）为何不成立：**

1. `origin` 现有三值同属**产出通道**轴：`compiled`＝编译器产出；`hybrid`＝表格骨架＋人工转写；`manual`＝人工录入（不经编译器）。`framework-internal` 记的是**出处类别**，不是通道。
2. 放进同一枚举即互斥。`STY-021` 现为 `origin: hybrid`，同时记录「骨架来自 1.2.4 表行」与「谓词人工转写」；改为 `framework-internal` 后，这条通道事实**再无字段可存**。反向若保留 `hybrid`，则「母本内生」这一出处事实不可见。
3. 合法组合无法表达：`compiled × mother-definition`、`manual × mother-row` 等在两值域中无值可写。
4. 与 3b 连锁：把 `manual` 收窄为通道后，枚举变成「3 个通道值＋1 个出处值」，只能靠「母本内生优先」的择一补丁维持，等于把两义混同换个方向复现。

**A′ 为何成立：** 两轴分离——`origin` 必填记通道，`source_class` 记出处类别，原 A 的语义由 `mother-definition` 承接。成本同为一次 0.13（母本行内改＋`project.py`），且无需改写 138 条既有 `origin`。

**原判断的可保留部分：** 「不得用 `origin: manual` 冒充母本内生出处」仍然成立，只是解法从「扩 `origin`」改为「增 `source_class`」。

## 6. 对其他 gap 的适用边界（以 D-CRD-1 流程管理器为例）

FIM-1 是**判据**，不是一次性特例；它可以被其他 gap 引用，但**不得自动套用**。

以 `D-CRD-1` 的 `CRD-007`（5.2.2 流程管理器，`@m:2477`）为例：

- **形式上海满足 F1／F2**：该行有「编排式 Saga 的泛化：管理有分支/并行/人工步骤的长流程状态机」这一自建定义，且 `row_id: "5.2.2-流程管理器"` 可反查。
- **但 F3 存疑**：定义句以上位概念「编排式 Saga」为基础，而书目 47（`@m:2760`）的登记面为「5.2.2 编排式/协同式 Saga 与步骤分类的操作化」。若书目 47 的「步骤分类」被认定覆盖流程管理器的泛化，则 F3 失败，必须走 `references`（书目 47），不能走 FIM。
- **结论**：D-CRD-1 **不能**因本 ADR 自动获得 `mother-definition` 身份；若将来要用，必须另立 ADR，提交 `CRD-007` 的 F1–F5 逐项证据，并先裁「书目 47 的步骤分类是否覆盖泛化行」。本 ADR 只提供判据，不预支该裁决。

**一般边界**：

| 情形 | 是否适用 FIM |
|---|---|
| 母本同节给出完整过程定义，且无书目登记该行 | 适用（须逐项过 F1–F5） |
| 定义以上位外部概念为基础，且上位概念已被书目登记 | 不适用（F3）——先裁书目覆盖，再决定 references 或 FIM |
| 母本只是表格外的举例、反模式标签、信号名 | 不适用（F1） |
| 条目字段需要外部参数／阈值 | 不适用或只能部分（F4） |
| 同一张表已有部分行被外部书目逐行登记 | 仍可逐行判定；但必须证明本行确无登记面，不能以「表内其他行有」推定本行有或没有 |

## 7. 反例（近似但不符合）

### 反例 A：分布式单体（纯提及，无自建定义）

母本 `@m:1362` 仅把它放在反模式槽：「分布式单体（服务间强耦合必须同步部署）；纳米服务（拆分过细）」；`@m:1385`、`@m:1683`、`@m:1954`、`@m:2176` 均把它作为**信号／反模式标签**使用。母本**没有**给出「分布式单体」的过程定义或判定规则。

- F1 失败：无自建定义行。
- 结论：不能登记为 `source_class: mother-definition`；它只能作为反模式名称出现在其他条目的 `anti_patterns` 槽，不构成独立方法的出处。

### 反例 B：绞杀者迁移（有定义，但外部书目已登记）

母本 `@m:1992` 有行内定义「以新单元渐进接管旧单元职责，旧路径按契约弃用节奏退役」，`@m:3656` 还有六步操作化序列。形式上 F1／F2 满足；但书目 34（`@m:2151`）与尾注 `@m:3859` 明写「书目 34《Monolith to Microservices》支撑 9.2.6 绞杀者模式」。

- F3 失败：外部书目已登记该概念。
- 结论：应走 `references`（书目 34），**不得**用 FIM 绕过 5.7 的既有登记面。这也说明 FIM 的边界：**有外部出处时，FIM 不是合法选项。**
