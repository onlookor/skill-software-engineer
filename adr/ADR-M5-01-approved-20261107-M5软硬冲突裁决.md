## 1. 决策问题

同一条款族内两处对 M5 的级别给出不可同真的表述：

- **0.17.5 L451**：「`draft→seed` = bootstrap 期专用迁移（**条件：M2–M6 全过**，0.17.6 人工种子通道），低影响……」
- **0.17.8 L507**：「`M5: narrative_sync(E): ∀ decision-bearing claim: formalized ∨ clue_flagged` —— **软（P2 抽查，积累升 P1）**」

同一摘要另见两处：0.17.6(1) L455「M2–M6 全过后迁移 seed」；0.17.7 L477「准入检查全部机器可判定（M2–M6）」，其第 5 项措辞为「narrative_sync：无未形式化的决策性叙事（**M5 预检**）」（L483）。

「M2–M6 全过」是闭区间摘要，M5 落在区间内：按字面执行则 M5 必须过；按 0.17.8 的级别定义则 M5 只是软项。本 ADR 裁决何者为级别权威，以及如何在不改动任何判据语义的前提下消解冲突。

## 2. 判定：0.17.8 为级别权威

**结论：0.17.8 L507 的「软」是级别定义；0.17.5 L451、0.17.6 L455、0.17.7 L477 的「M2–M6 全过」是摘要表述，不构成对级别的裁定。**

| # | 依据 |
|---|---|
| 1 | **摘要 vs 定义**。0.17.8 是 M 系列的逐项级别定义面（每项均标硬/软）；0.17.5／0.17.6 只是迁移条件的摘要引用，0.17.7 的「（M2–M6）」是准入清单的范围标签。定义面优先于摘要面。 |
| 2 | **0.17.7 自身措辞已松口**。L483 写「M5 **预检**」而非「M5 硬门槛」；L477 的「全部机器可判定」对一条 P2 抽查本就是伪陈述——摘要句在其自身段落内已自相矛盾。 |
| 3 | **P2 语义不可能同时是阻断**。9.2.1（L3582–3586）把 P0／P1／P2 的响应阶梯定为阻塞／限期整改／监测。0.17.8 给 M5 标 P2，它就不可能同时阻断 seed；判硬要改的不是一个词，而是「软→硬＋删『P2 抽查，积累升 P1』＋重排 9.2.1 映射」。 |
| 4 | **changelog 显示 0.17.5 迁移行是同日补丁**（L84/L86，v2.0 封版前补丁），目的是消解生命周期图与附录三 3.8「停留 draft」的张力，条件从既有摘要照抄，未重议级别；不构成对 0.17.8 的覆盖。 |
| 5 | **最小改动原则**。取软只需给摘要加一句解释；取硬要同步改母本、检查矩阵、代码 `SEED_CHECKS`、台账条件并触发方案甲重判。前者是澄清，后者是改判。 |

> **反方最强论点及回应**：0.17.7 的六项是「准入门槛」，第 5 项确实把 M5 列进去了。回应：清单回答「要查什么」，不回答「哪一项必须全过」；L486 只说「评估 = 门槛检查结果」，未把六项逐一设为 AND。故清单本身不构成「M5 硬」的独立证据。

## 3. 被否方案

### 3.1 取硬（否决）

| 后果 | 说明 |
|---|---|
| 当前 seed 受影响条目 | **0 条**（现测 138/138 通过、软警告 0）→ 硬化在今天就数据而言是空操作 |
| 判定语义 | M5 从「P2 抽查、累积升 P1」变为「阻断 seed／准入」；抽样检查被当作全覆盖门槛 |
| 与 9.2.1 冲突 | P2 的响应义务是「监测」；P2 项不可能同时是阻断门槛 |
| 与「积累升 P1」冲突 | 该设计前提是「先软后升」；一开始就硬，升级机制失去意义 |
| 需改动 | 0.17.8 L507、检查矩阵、`SEED_CHECKS`、`check_cst` 的 `failed` 集合、台账 `ST-STY-01.condition`，并触发方案甲重判（结果为空） |
| 误报风险 | `check_m5` 是关键词启发式（必须／不得／禁止／只能／应当），会把引用外部规范、转述反模式的句子判为「未形式化」；硬门槛下这些误报直接阻断 seed |

**否决理由**：取硬不是澄清而是改判；它与 9.2.1 的级别映射冲突，且把启发式抽查升格为全覆盖阻断，误报代价由 seed 准入承担。

### 3.2 选项 B（改写 0.17.5 L451 括注）——未采纳

改动 2 行（0.17.5 L451 与 0.17.7 L477 括注），表述更干净，但改写已发布条款正文，改动面大于选项 A 且失去原文可追溯性。

### 3.3 选项 C（0.17.8 L507 改硬）——否决

即 3.1 的取硬路径，另外还需删 P2 括注、同步 9.2.1 与全部下游实现。

## 5. 零语义变更论证

1. **未改任何判据的文字、范围与失败级别**：M5 的定义句（L507）、量词（∀ decision-bearing claim）、判据形式（`formalized ∨ clue_flagged`）逐字未动。
2. **未改任何检查行为**：`check_m5` 仍产出 soft 记录，仍计入 `SEED_CHECKS` 之外；`check_cst` 的 `failed` 集合不感知 M5；退出码不受影响。
3. **未改任何数据**：138 条 seed 与方案甲执行记录均不变；本裁决不产生状态迁移。
4. **只增加解释性语句**：新增句的作用是把「摘要 vs 定义」的既有解释次序显式化，不改变任一条款的真值条件。
5. **行数不变**：母本 4,447 行／围栏 216 不变；抽印同步后行数不变——故不触发 `@行号` 锚点位移。

## 6. 取软后保留的已知风险

| # | 风险 | 当前风险面 |
|---|---|---|
| 1 | 叙事可先于形式化入库：决策性叙事若无机器层承载者且无 `clue:`，只记软警告，条目仍是合法 seed，可被 S1 消费（消费时仅附注「依据种子条目，待重验证」，0.17.5 L448，不阻断） | 现测该类条目 **0 条** |
| 2 | 抽查不等于证明：M5 是 P2 抽查，「∀ decision-bearing claim」的完整性没有硬保证 | 结构性，不随条款变更 |
| 3 | 关键词启发式盲区：不用「必须／不得／禁止／只能／应当」表述的规范句（如「应」「要求」「保证」「只允许」）不被检出 | 结构性 |
| 4 | 软项不进 `SEED_CHECKS`：报告只留 warn，退出码不受影响 | 设计如此 |

## 7. 本 ADR 的边界

- 只裁决 M5 的级别口径，不涉及 M1–M4、M6–M9 的级别。
- 不授权改动 0.17.5、0.17.6、0.17.7 正文；这些摘要句维持原文，其解释以本 ADR 与 0.17.8 为准。
- 若将来要把 M5 升为硬，须新立 ADR 并同步 9.2.1 映射、检查矩阵、代码与台账；不得复用本 ADR。
- 本 ADR 取代原决策建议材料 `决策建议-M5-软硬冲突-2026-11-07.md`；该材料已删除，内容已全部并入本 ADR。
