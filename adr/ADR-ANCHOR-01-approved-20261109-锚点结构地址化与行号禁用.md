## 1. 背景与问题

### 1.1 触发

B7 物理分区会在文档头插入阅读地图，随后整条搬移 21 个条款，使母本全文件行号位移。当前 LIVE 的 **8,831 条行号锚**（裸行号 8,681 ＋ 带前缀 150）全部是**非结构地址**，其中 7,373 条指向母本。B7 之后这些锚全部指错行。

### 1.2 实测（2026-11-09，只读）

|---|---:|
| F-1（LIVE 内非结构地址锚：裸行号＋带前缀行号） | **8,831**（裸 8,681＋前缀 150） |
| 其中指向母本／registry／其它文档／adr | 7,373／1,449／9／0 |

| B3a 首个改动点 @128 之后受影响的母本锚 | **7,051** |
| B7 之后仍正确的母本锚（目标行 ≤24） | **1** |

### 1.3 为什么「计数不变」不能当验收

B1 只插入 57 行，F-1 仍是 8,681、targets 仍是 13,396、F-3 hard 仍是 0，但 6,773 条锚已经指错内容。**计数判据从 B1 起就是假绿**，B7 只是让它彻底暴露。若继续以行号为锚，B1–B7 需要 8 张映射表、合计 **51,200 行**，且此后每次编辑都要重生成。

### 1.4 为什么逐字片段不能当机器键

本仓实测：同条款内前 12 字碰撞 **295 处**（`锚点与引用规范.md` §3.1）；九条同型表格注中 8 条 **237 字符逐字相同**（5.2 @2460 为 304 字符）。文本只用于识别内容，不能用于标识身份。

## 3. 新锚的形式化定义

### 3.1 语法

```
anchor    ::= "@" target ":" locator ["#" sub] ["~" end]
target    ::= "m" | "r" | "p" | "v" | "c" | "d"
locator   ::= clause_id            // m: 1.2.3
            | entry_id             // r: STY-021
            | profile_name         // p: STY
            | term_name            // v: grounded
            | section_name         // c: 3.2
            | rel_path             // d: registry/scripts/project.py
sub       ::= "head"
            | "row-" table_id "-" row_name ["-" secondary]
            | "li-" ordinal ["." ordinal]
            | "p-" ordinal
            | "field-" dotted_path
            | "key-" dotted_path
            | "sec-" title
            | "fn-" name
end       ::= anchor | clause_id | ordinal
```

**删除**：`locator ::= 行号`。`@m:3706`、`@r:1200` 一律判不合规。

### 3.2 字段语义

| 元素 | 地址 | 说明 |
|---|---|---|
| 条款标题 | `@m:<clause>` | 定位到标题行；唯一 |
| 表行 | `@m:<clause>#row-<table_id>-<row_name>` | `table_id` 取表前标识；`row_name` 取首列；同名时加 `secondary` |
| 列表项 | `@m:<clause>#li-<N>` | 条款内 1-based；嵌套写 `li-2.3` |
| 正文段落 | `@m:<clause>#p-<N>` | 条款内非表格、非列表、非围栏的正文段落 1-based |
| 注册表条目字段 | `@r:<entry_id>#field-<path>` | 如 `@r:STY-021#field-provenance.source_class` |
| 代码符号 | `@d:<path>#fn-<name>` | 与现有 `#fn-` 一致 |
| 缺口 | `@!GAP:<id>` | D4 既有形态；不参与解析失败计数 |

`quote-` **不是** sub；需要人眼核对时写在锚点之后，用 `〔逐字：…〕` 包裹，解析器忽略。

### 3.3 唯一性规则

1. `resolve(anchor)` 必须解析到**恰好一个结构单元**；0 个＝F-2，≥2 个＝F-9。
2. `(clause_id, sub)` 在文档内唯一；表行键按规范 §3.1 的「表标识＋行名＋次级键」，冲突即 fail，不降级、不猜。
3. 文本相同不构成地址；不得以「第一个匹配」消歧。

### 3.4 稳定性规则

| 操作 | 地址是否变 | 检测 |
|---|---|---|
| 整条搬移（含 B7 五段分区） | **不变** | F-10 期望 0 变化 |
| 在条款**外**插入/删除 | 不变 | F-10 |
| 在条款**内**插入/删除段落 | 其后 `p-N` 变 | F-10 逐条列出 |
| 在条款**内**插入/删除列表项 | 其后 `li-N` 变 | F-10 逐条列出 |
| 改条款号 | 禁止（0.22.1） | 条款号唯一性检查 |
| 改表行首列 | 该行地址变 | F-2／F-10；必须显式登记 |

### 3.5 适用范围与冻结豁免（新增，D3）

- **LIVE**：`registry/` 下 yaml、`registry/README.md`、四个 `registry/projections/*.md`、`参考资料缺口核对报告.md`。新规则只约束这 9 个文件。
- **FROZEN**：`软件工程元框架成文法-changlog.md`、`todo.md`、已批准 ADR、`R2提案-*`。**按 as-of 保留原引用形态，不重写、不计入违规**；检测器只出 INFO-2 快照（当前冻结侧行号锚 **2,937** 条＝裸 2,928＋带前缀 9，其中指向母本 1,819 条）。
- **sandbox**：方案、施工单、样张、规范正文等。既不判失败，也不计入 INFO-2，只标 `ignored`。
- 同一文件同时命中 FROZEN 与 LIVE → 配置错误 CFG-01（hard），停批。
- 冻结文件转入 LIVE（或重新激活）时，**在转活跃的那一批内完成迁移**；不允许「转活跃但保留旧锚」。

## 4. 0.22 逐款草案

> 事实前提：锚定语法正文在**编译规范 3.2**，0.22.1 已明写「锚定语法本身归编译规范」。因此本节只改承诺与豁免，语法改 §5。

### 4.1 0.22.1（@1134–1138）末段追加一句

> 引用锚点必须由**稳定结构地址**构成：条款号＋款/行/子节路径＋条目 ID／谓词 ID。行号、页码、字符偏移**不得**作为锚点地址；带目标前缀的行号（如 `@m:123`）同样禁止。逐字片段只作人眼复核，不作机器定位依据。语法与唯一性判据见编译规范 3.2。

### 4.2 0.22.2 承诺一（@1142–1147）追加第四条

> - **结构地址稳定性**：条款内每个可被引用的单元（标题／表行／列表项／段落）必须可由「条款号＋子路径」唯一寻址；新增单元不得改变既有单元的地址。同一文本出现多处**不构成**地址；文本相同不得作为定位依据。

同款映射表义务补一句：

> 映射表按**条款号／行 ID／性质 ID**记 `v_old ↔ v_new`，**不按行号记**；物理分区（整条搬移）属「重组」，须出表，但表内不登记行号。

### 4.3 0.22.2 新增承诺四（冻结豁免）

> **承诺四（适用范围与冻结豁免）**：本节只约束活跃文件集合（`registry/` 下 yaml、`registry/README.md`、四个投影、`参考资料缺口核对报告.md`）。冻结文件（changlog、todo、已批准 ADR、R2 提案）按 as-of 保留原引用形态，**不重写、不计违规**。冻结文件转入活跃集合时，须在转活跃的同一批次内完成迁移。

### 4.4 0.22.4（@1184–1190）追加形式化谓词

```
anchor_address(clause_id, sub_path, stable_id, version)
anchor_unique(clause_id, sub_path)        // 同条款同子路径恰一落点
anchor_stable(anchor, reorg)              // 重排前后解析位置不变
```

### 4.5 编辑方式约束

0.22 的四处改动一律**同行追加或列表项追加**，不新增正文段落，以保持 0.22.2 内现有 2 条 `p-N` 锚的序位不变。改完必须复跑：这 2 条锚仍解析到原文；否则列入 B−1 变更清单。

### 7.7 F-3 soft 的口径（1,052 条实测）

- 当前实现的 soft 只读 `legacy`／`prefix` 行，判据是「锚点前 15 字符内最后一个条款号 ≠ 落点所在条款号」。**迁移后 live 行锚为 0，该口径的 soft 必为 0 —— 这是空测，不是达标**，与 F-9 的空测同病，不得当作新基线。
- 实测 1,052 条里：**1,041 条（99.0%）** 的邻近条款号在目标文件中确实存在，只是与本条不同（正常交叉引用，如 @3653-3659 落在 9.2.4、邻近文本写 9.2.5）；**11 条** 邻近数字不是目标文件的条款号（列表序号、编号缩写），属启发式噪声。**指纹不符 0 条**：F-3 的指纹比对尚未实装，不能记作「实测 0」。
- 因此 `B0` 重冻前须把 F-3 soft 改为作用于**结构锚**（相邻条款号＋基线指纹），否则保留的是一条永远为 0 的检查。该改动属判据变更，须单独批准后实施。

## 9. 与 ADR-LAYER-01 的边界

- 两者**独立**：本 ADR 解决「引用会不会失效」，LAYER-01 解决「条文放哪里」。即使不做三层分区，行号锚在任何编辑下也会漂移，本 ADR 仍然成立。
- **顺序**：B−1 先于 B0，B0 先于 B1。LAYER-01 未签批时 B−1 仍可单独执行（它不改条款归属）。
- **回退**：B−1 回退不影响 LAYER-01 的批次；LAYER-01 回退也不要求回退 B−1（结构地址在旧布局下同样有效）。
- **不挂靠**：本 ADR 不写在 LAYER-01 的 D1–D8 中，避免「回退分层必须连锚点体系一起回退」。
