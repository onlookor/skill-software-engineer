## 1. 背景与问题

冻结清单第 4 项（方案 (c) 问句式硬检查）长期未解冻，根因是 `applicability` 只有"三键列表"的半结构化形态：

- 全库 `applicability` 项 762（138 条 × 三空间），全部为**裸字符串**；它既可能是可求值谓词，也可能是一句"评审要回答的问题"。
- PRJ-001…PRJ-011 的首项实为问句（"…必须由 {谓词集} 回答"），却与真谓词同形；任何基于文本的判据（含"含问号即失败"）都会误伤或漏判。
- 0.4 条件 3 要求"有出处"，但裸字符串没有可单独取出的出处键；问句的"由谁回答"也不可机器解析。

本轮把"项"从纯文本升级为**项级对象**：保留原文，新增"形态声明 ＋ 按形态的必填出处"。

## 3. 槽形态

`applicability` 仍是三键对象；每键仍是列表；**列表项**变为二态：

```yaml
applicability:
  problem_space:
    - expr: "[架构评审场合存在，且「系统整体组织原则是什么」必须由 {1.5 拓扑谓词集} 回答]——@3891 第二列逐字；该问题不得以单张局部图或叙述替代"
      form: question
      answered_by: "@m:10.2.1"
    - expr: "一切跨边界数据流动（方面 4 的入口）…"
      form: predicate
```

| 字段 | 类型 | 必填 | 取值域／约束 |
|---|---|---|---|
| `expr` | string | 对象态必填 | 原文逐字，不得二次改写；裸字符串态等价于 `expr` |
| `form` | enum | 对象态必填 | `predicate`（可求值）／`question`（评审待答，不承载真值）／`slot`（参数化） |
| `answered_by` | string | `form=question` 必填 | 条款号（如 `@m:10.2.1`）、条目 id、或可解析的母本行号 |
| `slot_name` | string | `form=slot` 必填 | `^[a-z][a-z0-9_]*$` |
| `value` | 任意 | 选填 | 给出即须同给 `source`（0.4 条件 3） |
| `source` | source_ref | 随 `value` 必填 | `source_type` ∈ `{clause_id, bib_id, row_id}`，且可解析 |

**为什么不在既有字符串里塞结构化内容**：①"散文串解析"必然退回猜句子，正是脆弱判据的来源；②文本内嵌标记会造成"原文／标记"双重真相，改写时无法证明原文未被改；③`source` 必须是可单独取出的键，才能被 0.4 条件 3 与指针反查消费。

**为什么不新增第 16 顶层字段**：0.17.2 是 15 字段封闭集；新增顶层字段会使 138 条存量全部一次失败，并牵动 18 份剖面与四件投影列结构，代价与收益不成比例。

## 4. 与 0.17.2 的关系

**判定：路 A（既有字段内加子结构）**。

- 15 个顶层字段、`APPLICABILITY_FIELDS`（三键）、剖面的 `required` 公式、四件投影的列结构**全部不变**。
- 存量兼容：裸字符串 ≡ `{form: predicate}`；138 条条目无需全量改写。
- 消费面仅 3 处需适配：`project.py` 的 M2 applicability 列表断言、M4 谓词扫描（改用 `expr_of`）、占位符路径映射（`applicability.<space>[i].expr` 仍映射回 `<space>` 类目）。
- 实测：投影零改动（仅计数文案与时间戳）；`profiles.yaml` 剖面零改动；占位符总数 1,483 不变。

## 5. 判据（R2-A1～A4）

| 判据 | 级别 | 内容 |
|---|---|---|
| R2-A1 结构 | 硬（info 期降 info） | 首期受管项（非 SRC 的 `problem_space[0]`）必须是含非空 `expr`、合法 `form` 的映射；对象项不得含未知键；非受管项的裸字符串按 `predicate` 兼容 |
| R2-A2 角色 | 硬（info 期降 info） | `form=question` 仅准 `problem_space`；`answered_by` 必填且可解析（条款号／条目 id／`@m:` 行号） |
| R2-A3 槽 | 硬（info 期降 info） | `form=slot` 必有合规 `slot_name`；给 `value` 必给可解析 `source` |
| R2-A4 形态提示 | info（恒不阻断） | H1：`predicate`／裸字符串含疑问标记；H2：`question` 不含疑问标记。只提示复核，不判失败 |

**灰区处置**（一律 info，不进硬判据）：

1. 复合项（同一项既陈述条件又提出问题）——以 `expr` 整体归类，不拆分；
2. 含"是否／哪些"等字样的**真谓词**（如 CTR-005 的"按『是否跨边界』收窄"）——允许保持 `predicate`，仅产生 H1 提示；
3. 槽名未定、`value` 暂缺的 `slot`——允许无 `value`；求值期记 `unknown`（0.18 S1），不判失败。

**回退方式**：`profiles.yaml` 的 `check_switches.R2_APPL` 单键切 `hard|info|off`（默认 `info`）；不需要回改任何条目数据。若需整体撤销，`git revert` 本 ADR 对应提交即可（单笔、无跨批依赖）。

## 6. 11 条 seed 的处置

全部为 `form: question` ＋ `answered_by: "@m:10.2.1"`；`expr` 逐字保留原文（含既有 `@` 行锚），**不编造 `value`／`source`**。

| 条目 | 原文要点（`expr` 逐字保留） | 新判据下 |
|---|---|---|
| PRJ-001 | 架构评审场合；「系统整体组织原则是什么」须由 {1.5 拓扑谓词集} 回答 | question，非待定事实 |
| PRJ-002 | 分解评审场合；「单元边界与依赖」须由 {2.5 边界谓词集} 回答 | question |
| PRJ-003 | 数据评审场合；「数据所有权与流动」须由 {Y 谓词集、血缘} 回答 | question |
| PRJ-004 | 流程评审场合；「行为与协调的时序、事件流与流程状态」须由 {Z 谓词集} 回答 | question |
| PRJ-005 | 验证评审入口；「验证计划与证据索引」须由 {T 谓词集} 回答 | question |
| PRJ-006 | 守护评审场合；「守护台账与健康度」须由 {G 谓词集、演化路线图} 回答 | question |
| PRJ-007 | 批准角色须回答「这个高影响决策该不该批」 | question |
| PRJ-008 | 抽查评审人须回答「低影响决策是否免于留痕」 | question |
| PRJ-009 | 抽查评审人须回答「材料性判定是否被机械适用」 | question |

**结论**：11 条中没有一条是"真未定事实"，它们陈述的是"评审该回答什么问题"；问题本身不承载真值，故标 `question` 而非编造 `value/source`。**不触"逐批追加不改写历史"红线**：原文逐字保留在 `expr`，只加外壳。
