## D2 条目 schema 与键名映射

- **D2.1 逐字采用**：条目 schema = 母本 0.17.2 **逐字采用**，不重定义、不扩展、不裁剪（编译规范 2.4）。〔母本派生〕
- **D2.2 键名映射**：YAML 侧仅做键名书写映射，语义零变更：

| 0.17.2 / 编译规范 2.1 | 本目录 YAML 键 |

| `version`（语义版本 `{major, minor, patch}`） | `version: {major, minor, patch}` |
| `row_id`（表格行 ID） | `"{表号}-{行名}"`，如 `1.2.1-分层` |

〔母本派生〕
- **D2.3 字段封闭与顶层节**：条目内**不得出现 0.17.2 之外的字段**。注册表级信息（缺口、状态迁移简记、Waiver、人工判断登记、未闭合的冲突矩阵行）一律置于 `method_registry.yaml` 的**顶层节**，不进入条目。〔母本派生〕
- **D2.4 状态迁移简记 schema**：`status_transitions` 每条固定九字段 `transition_id`／`from`／`to`／`scope`／`date`／`condition`／`evidence`／`impact_level`／`provenance`，可选 `note`。`from`／`to` ∈ {`draft`,`seed`,`active`,`deprecated`,`retired`}。**撤回型 `seed→draft`（ADR-LC-01 §3.6）另需四字段**：
  - `seed_rejudication_ref`：重判批次号，指向同次重判的 `seed_rejudication` 差异记录；
  - `consumption_checked`：布尔，`true` 表示已查存量消费；

  且 `impact_level` 必须为「高」（与 `active→deprecated` 同构）。`draft→seed` 的 `impact_level` 维持「低」。缺项由 `check_ledgers` 判硬失败（`CHECK-SPEC` C4.7）。〔ADR-LC-01 §3.2／§3.6〕

## D3 谓词书写约定（M4／M15 的校验对象）

- **D3.1 词汇封闭**：`applicability` 三空间谓词、`anti_patterns.detection_predicate`、`signals[].detection_predicate` 与 `signals[].severity_condition.when_predicate` 只能使用 `predicate_vocabulary.yaml` 登记的谓词名（编译规范 2.3「谓词名注册」）；缺失词汇 → R2 提议，**不得本地造词**；同时登记为 `gaps`。四个字段由同一检查 `M4` 硬校验（2026-11-08 ADR-SRC-P0-06 由前两字段扩至四字段；`G-SRC-1` 据此闭合）。〔母本派生 0.17.8 M4／编译规范 2.3〕
- **D3.2 语法**：联接 `∧`、析取 `∨`、否定 `¬`、蕴含 `→`、量化 `∀`／`∃` 前置、通配 `·`（编译规范 2.3 BNF）。〔母本派生〕
- **D3.3 谓词槽与事实占位**：方括号 `[…]` 表示**谓词／参数槽**——`applicability` 三空间与 `detection_predicate` 是谓词，`cost_profile`／`envelope.bound_expr` 是参数；它们在决策期求值，**不计事实债**。待勘察事实必须带显式标记：以 `待勘察：` 开头，或整句以 `待勘察` 结尾；仅句中提及不计。`[已核验]`／`[存疑]`／`[未核验]`／`[待核验]` 按 0.12 是可信度标注，单列统计。事实占位求值 `unknown` 时按 M15：候选保留＋勘察义务登记，**禁沉默排除**（0.18.6）。旧口径（全部方括号计事实占位）按 §4.17 迁移记录不回改。〔2026-11-04 新口径，本轮确立为规约〕
- **D3.4 公式约定词**：`approved`／`declared`／`registered`／`sourced`／`compatible`／`has`／`now` 按编译规范 2.3 内建语义表使用，不算白板谓词。〔母本派生〕
- **D3.5 三值语义**：`{true, false, unknown}`；两值实现 = 编译缺陷（编译规范 2.3(3)）。〔母本派生〕
- **D3.6 待裁名单**：`predicate_vocabulary.yaml` 的 `pending_review` 收录「母本有出现、但无逐字定义或元数不可判定」的名字；该名单**不计入在册名数**，裁决前不得入三组、不得合并／改名／加别名。〔新立：2026-11-07 第四批（`consumed_by`）〕
- **D3.7 显式占位与投影边界**：实参个数须满足 D3.8 的判定式；**少给的槽位一律用 `·` 显式占位**（如 `dsm(system)` → `dsm(system, ·)`），**裸缺参按错误处理**，不再默认按「前缀投影」放行。`·` 表示**该槽有意不约束**——槽位存在、参与元数计数，但不施加任何条件；写漏表示**该槽未出现**——元数不成立、表达式真值不可判。二者差一个实参位，语义差「有意的空」与「缺失」；前者合法、后者由 S-12 硬失败。凡补 `·` 处，ADR 须逐条说明该槽为何可以不约束。**投影判据**：`f(…)` 后**紧邻** `.槽名` 的表达式才是投影，只可用于「引用某槽的具体值」；须处于值位（比较式一侧／函数实参／赋值右值），不得作 `∧`／`∨`／`¬` 的直接布尔操作数，也不得替代一次完整调用。满足上述条件者 S-12 不计 arity；无 `.槽名` 的裸缺参不适用本条。母本既有投影写法（`interaction_flow(F).kind` 之类）保留合法性（母本是定义面）；数据侧如需投影，须按本判据书写。2026-11-08 起 S-12 为 hard；谓词词表 `arity` 登记值不变。〔新立：ADR-SRC-P0-08〕
- **D3.8 可变长槽的 ≥N 判定**：词表条目带 `variadic: true` 者（目前仅 `registry_entry`，`arity: 6`，母本 @493 末槽 `fields...`），元数判定为 **`argc ≥ arity`**（`argc` 为实参个数）；尾部可变槽可以加长，但**前 N 个固定槽位一个都不能少**，缺位仍须写 `·`。其余条目为 **`argc = arity`** 恰好相等。`arity` 字段仍登记全部槽数、不改。含可变槽的调用在 `--check` 报告中**单列计数**，不与固定元数调用合并统计。〔新立：ADR-SRC-P0-08，2026-11-08 用户裁定「≥ 6」〕
- **D3.9 背景守卫不得入检测式**：`detection_predicate` 是**个体判定式**，只约束 `∃` 见证及其属性；「本条反模式／本族条目已在册」属**背景条件**（在注册表已装载的前提下恒真），不得写成 `registry_entry(...)` 之类的合取项放在检测式里，也不得以 `·` 填满槽位来伪装成一次有效调用。该类事实由注册表侧静态检查接管：条目存在与编号由 C-ID，schema 与字段完备由 M2，kind 剖面与族齐备由 C-KP，seed 覆盖宣称（含 `seed_source.table_rows` 逐表行数与 row_id 分布核对）由 META。检测式里出现恒真背景守卫，按「伪装成个体判定的背景条件」处理，须移除并记录接管者；确需保留族级断言时，应写成独立检查，而不是塞进逐条检测式。〔新立：ADR-SRC-P0-09，2026-11-08〕
