# F-5 同条款行键重名：成因与方案（待裁定，未执行）

> 状态：只做诊断与方案对比，**本文件不改任何行键、不改母本**。检测器当前 F-5＝fail，58。
> 口径：`anchor_index.py` F-5 对目标文档（`m`／`r`／`p`／`v`／`c`）的 markdown 表体按 `(文档, 条款号, 首列规范化值)` 分组，`count>1` 计重复。

## 1. 成因

不是单一原因，两类同时存在：

1. **同一 `clause_id` 下有多张表**：条款号只到 `x.y.z`，不区分表。`0.21.2` 下 5 张状态机表、`0.21.3` 下 5 张迁移表、`1.4/7.4/8.4/9.4` 各 2 张「来源／目标方面」表、`10.7` 下 6 张不同表，首列名字在表间重复。
2. **同一张表内首列就重复**：首列不是本表的唯一键。`0.21.3` 的迁移表内 `from` 多次出现（同一 `from` 到不同 `to`）、`10.7` 的链表 9 行首列同为「CH-E 回溯链」、`10.4` 单表内「全部方面」两行。

因此 58 处 = **跨表重名 29 处 + 表内重名 29 处**。只按表编号（方案 B）最多消掉 29 处，剩下 29 处仍是重复。

## 2. 方案

三案均**只在解析侧改行键推导**、不写母本正文；行键不落盘，故无数据迁移。示例写在围栏内，不构成正文引用。

### A. 同条款内同名序号后缀

```
@m:0.21.2#row-draft      → 第 1 次出现的 draft
@m:0.21.2#row-draft-2    → 第 2 次出现的 draft
```

- 改哪里：`anchor_index.py` 行键推导（按 `(doc, clause, 首列)` 出现序追加 `-2`／`-3`……）＋ F-5 判重口径；规范 §3 增一条后缀约定。
- 改动条数：**58 处重名实例改名**；其余 221 行键不动。
- 母本：**0 行**（键在解析时生成）。
- 现有引用：0 条需改；profiles `N 行`：0 处。
- META／M2：不受影响。`version`：母本与 registry 条目不升；规范需记一条变更（规范无版本字段）。
- 回退：revert 一处推导函数＋规范一段；无数据迁移。
- 风险（重要）：子锚键内部已用 `-`（如既有 `#row-同步请求-响应`），`#row-同步请求-响应-2` 无法判定是「第 2 次出现的『同步请求-响应』」还是「名为『同步请求-响应-2』的行」；`10.7` 有首列字面为 `1`…`21` 的行，`#row-1` 同时是名字与序数。解析器会静默取首个匹配。

### B. 条款内表编号

```
@m:0.21.3#row-3-draft    → 该条款第 3 张表的 draft 行
```

- 改哪里：同上，表序取同条款内表块出现序；规范 §3。
- 改动条数：**279 行全部换键**（25 张表都要加表序，命名空间变了）；仅改重名行会与未改行产生两套键，不可行。
- 消除：跨表 29 处；**表内 29 处不消除**，F-5 只从 58 降到 29（仍 fail）。
- 母本：0；现有引用：0；profiles `N 行`：0；META／M2：不受影响；`version`：同 A；回退：同 A。
- 风险：表序是位置量，在条款内插入新表会整体后移；首列指纹不变，F-3／F-5 不会报警 → 静默错指。要 pass 必须再叠表内行序，等于退化为 C 的一部分。

### C（建议）. 表级语义命名空间＋表内复合键

```
@m:0.21.2#row-SM-CT-draft
@m:0.21.3#row-SM-DR-under_review-approved
@m:1.4#row-目标方面-全部方面-2
@m:10.7#row-链-CH-E回溯链-3
```

- 表标识取表自身语义，不用位置：`0.21.2`／`0.21.3` 用紧邻的 `SM-xx` 小节码（SM-DR／SM-CT／SM-WV／SM-CA／SM-GS，实际单表可用 `SM-xx` 直接判唯一）；`1.4/7.4/8.4/9.4` 用表头「来源／目标方面」；`10.7` 用表头语义（原始条目／条目／术语-A／术语-B／方面／链）。表内重复再叠第二维：迁移表用 `from-to` 天然复合键，其余用表内行序。
- 改动条数：**279 行换键**（其中 29 处表内重复由第二维消歧），F-5 → 0。
- 母本：0；现有引用：0；profiles `N 行`：0；META／M2：不受影响；`version`：母本／registry 不升，规范补 §3 作用域与复合键两段。
- 回退：revert 推导函数＋规范；无数据迁移。
- 风险：表标识依赖小节标题／表头，重命名会**响亮失败**（子锚解不出 → F-2 fail），而不是静默错指；需在规范里固定「表标识不得随排版变化」。

## 3. 不可逆点与静默损坏

- **不可逆点 1（须避免）**：把后缀写进母本表体首列文本以求唯一——那是 58 行母本文本改动，须走 0.22 版本递增与 ADR，且改写了规范正文，**本方案三案都明确不做**。
- **不可逆点 2**：一旦把新行键写进 registry `source_type: row_id` 或正文锚点，回退就从「revert 一处函数」变成多文件迁移。当前实测 0 条，故三案此刻都可逆；**建议在裁定前不要新增 `#row-` 引用**。
- **会静默坏掉的**：A 的 `-` 歧义与数字行名冲突、A／B 的位置序在插入表／行后整体错位——三种情况首列指纹都不变，检测器不报，引用会静默指到相邻行；C 的语义标识在改名时是硬失败，可被 F-2 抓住。
- **共同前提**：`10.7` 两张「术语」表表头同为「术语」，C 需用其前置小节（`A. 行业缩写`／`B. 通用术语`）区分，否则该组仍重名。

## 4. 结论

- 只做表编号（B）不能收口，且要 pass 必须再叠行序；纯序号（A）能收口但与既有 `-` 命名冲突、位置不稳。
- 建议采用 **C**：语义表标识＋表内复合键/行序，一次把 58 降到 0，且不触碰母本、不改 profiles 的 `N 行`、不影响 META／M2。
- 等裁定后再实施；实施前再跑一次 F-5 现状值（本轮未改行键，58 不变）。
